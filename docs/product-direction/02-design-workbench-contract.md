# PD-02 — Design workbench contract

Status: future product direction; not implementation authority.

## Purpose

Define the target Design information architecture after the maintainer-approved Process and BLUECAD beta mockups.

## Design navigation

The normal Design workspace contains exactly two peer work modes:

- `Process`
- `BLUECAD`

Do not keep `Model`, `Results`, or `Lineage` as permanent peer tabs in normal Design navigation.

`Process` and `BLUECAD` remain separate full workspaces because they are different editing environments with different tools and semantics.

## Shared Design context strip

Both workspaces should expose a small, unobtrusive contextual status strip instead of separate Model/Results/Lineage pages. Intended information includes, when available:

- current model/version anchor;
- currentness/staleness state;
- Process validation/result summary;
- BLUECAD validation/result summary;
- latest relevant run anchor;
- unresolved proposal/stale dependency count;
- source/lineage anchor.

Example only:

`Model v13   Current   Process ✓   BLUECAD ✓   Run #188   2 stale`

Each item should deep-link/open the relevant owning record or drawer. The strip must not duplicate canonical state.

## Model semantics

A Model is not a third editor. A model/version is the authoritative engineering dossier for one exact version of the engineering solution and belongs in `Memory > Models`.

A model version may aggregate or reference:

- engineering question/scope;
- requirements applicable to that version;
- assumptions;
- equations/methods;
- canonical parameters and inputs;
- Process configuration;
- BLUECAD geometry/configuration;
- outputs/results;
- validation state;
- criticalities/known limitations;
- notes/future work specific to that version;
- linked literature/source records;
- generated artifacts;
- linked runs;
- parent/superseded lineage.

A validation such as `geometry PASS` or `process FAIL` has meaning only in the context of the exact model version/run/evidence that produced it. Do not create a separate global Evidence area that implies a PASS remains globally true after the model changes.

## Results semantics

Results are contextual outputs of an exact model version/run/analysis. They should normally appear:

- in Process/BLUECAD context while actively working;
- inside the exact model version dossier in Memory;
- inside a selected run when historical details are inspected.

A separate global Results destination is not part of this product direction.

## Lineage semantics

Lineage is a transversal property, not a normal primary workspace. Records may expose relations such as:

- derived from;
- supersedes;
- source of;
- generated by;
- used by;
- affected by;
- run against;
- imported from.

A compact drawer/graph may visualize these relations. Lineage must remain tied to canonical provenance records rather than becoming a second record store.

## Process approved layout constraints

The approved Process beta direction includes:

- narrow persistent primary rail;
- workspace header with `DESIGN`, `Process workspace` and Appearance control;
- full-width Process toolbar;
- left equipment/process navigator;
- large light warm-grid central workspace;
- right inspector split vertically into Jarvis and editable Properties;
- right-side Jarvis and Properties are stable components and should not be reinvented in adjacent workspaces without a product reason;
- Properties values are visibly editable where the selected engineering object permits editing;
- no green ambient wash behind the engineering canvas;
- nearly square surfaces/controls.

The repository visual reference PR for this approved Process target is intentionally documentation-only and does not by itself authorize runtime layout changes.

## BLUECAD approved layout constraints

The approved BLUECAD beta direction deliberately reuses the Process shell and right inspector structure.

BLUECAD changes only the semantics needed by CAD:

- left side becomes model/feature navigator rather than Process equipment;
- toolbar contains CAD tools and uses official Phosphor icons;
- center is a dominant 3D viewport with selection context;
- selection drives CAD-compatible Properties such as geometry/material/dimensions;
- a low/collapsible technical dock may expose constraints, validation, measurements, analysis and messages;
- versions/exports/studies are subordinate navigator concepts, not primary application pages;
- do not rebuild the approved Jarvis/Properties component merely because the active workspace changes.

## Non-goals

This contract does not authorize an Aspen-like editable flowsheet beyond existing accepted authority, a new CAD kernel, a new solver, or any runtime implementation. It freezes product composition only.
