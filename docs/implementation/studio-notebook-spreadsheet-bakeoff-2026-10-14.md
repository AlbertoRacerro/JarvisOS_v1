## Deviations from the contract (read first)

1. 187 runtime is in `backend/app/modules/studio_runtime/runtime.py` (`run(RunRequest)`). It ro-binds only `sys.prefix` of the process that calls it as the sandbox Python environment, and the worker runs `python -I` with a cleared environment. Marimo is not installed in the repo backend venv and must not be added (that is a dependency/manifest change, which the spec forbids). The repo-venv run is recorded as a finding (Q1). All marimo measurements inside a sandbox use the **unmodified repo 187 runtime code** (`PYTHONPATH=backend`) invoked from a scratch venv (`mvenv2`: marimo 0.25.1 + pydantic 2.13.4), so `sys.prefix` is the scratch venv. This is the same bwrap argument vector, limits and worker, but it is **not the 187 runtime as deployed** (different mounted environment). It is labelled "scratch-venv 187" below.
2. Browser evidence is from a scratch static server (`python3 -m http.server`, single origin `http://127.0.0.1:4192`) serving the scratch Vite `dist`, not a candidate backend serving `frontend/dist`. Same-origin property holds; backend is absent. Headless Chromium uses software rendering, so frame times are not GPU-representative.
3. "Cold" start was not cold-cache (no page-cache drop); values are first-in-process, warm-disk.
4. The XLSX round trip is not a Univer feature (see U5); it was measured with exceljs 4.4.0 (MIT) as a stand-in and is labelled so. The CSV exporter is my own 6-line serializer over Univer `getValues()`.

## Q1-Q5 answers

- **Q1 marimo containment.** Partly. A marimo notebook run as a one-shot script (`python nb.py`, `app.run()`), plus `marimo export script` and `marimo export md`, run inside the 187 bwrap shape with no kernel server, no host-reachable socket, no surviving process. But (i) marimo is not importable in the real 187 runtime (repo venv), and the runtime mounts only its own `sys.prefix`, so making marimo available means adding it to that environment (a dependency change, not allowed by this spec) or changing which environment 187 mounts (a boundary change); (ii) the only HTML export (`marimo export html`) starts an edit-mode kernel via a loopback `Listener` and a spawned process: impossible inside 187, and outside it opens a host loopback port and runs unsandboxed. So containment holds only for non-HTML shapes.
- **Q2 marimo data in.** Yes for the measured mechanism: a JSON snapshot passed as `RunRequest.inputs` and embedded in the notebook source, with no DB path, token or project root in the sandbox. The total request, including source and metadata, remains below the 187 cap of 131,072 bytes.
- **Q3 marimo data out and provenance.** Partly. `.py`/script/md exports are byte-stable and small, and the 187 `RunRecord` gives source SHA-256 (of the wrapper source); I computed notebook and snapshot SHA-256 inside the run. The 187 result cap is 64 KiB. HTML is not producible under 187, and where it can be produced it depends on cdn.jsdelivr.net at view time. Run-record provenance for an HTML artifact does not exist in the shape allowed.
- **Q4 Univer embedding.** License yes (all permissive, no Pro import), network yes (same origin only, no telemetry/CDN request seen), initial bundle yes (0 B added), but lazy-chunk cost is 1.74 MB gzip, above the 1.5 MB threshold. Not measured: whether importing individual packages instead of the presets bundle drops it under 1.5 MB (the spec treats marginal as reject and this was not marginal; no retry performed).
- **Q5 Univer authority.** The sheet can be fed a frozen plain-object snapshot and saved as snapshot JSON with no network path to any Parameter/model write (scan + zero non-static requests). CSV export was supplied by application code. The measured OSS prototype had no XLSX export path; exceljs (MIT) provided the separate round trip and its 193 transitive packages were not license-audited for adoption.

## Criteria not measured or only partly measured

- Marimo telemetry/usage-ping behavior outside the sandbox was not traced (inside the sandbox the network is absent).
- Optional marimo extras, and exceljs's 193 transitive licenses, were not audited.
- U2/U3/U5 were not run against a candidate backend serving `frontend/dist` (scratch static server instead). The accepted spec permits prototype browser evidence for a decisive rejection; adoption would require the candidate-backend proof.
- M4 cold start not measured with a dropped page cache.
- Whether an in-repo Univer module would avoid importing any API client (U4) can only be shown on a real implementation.
