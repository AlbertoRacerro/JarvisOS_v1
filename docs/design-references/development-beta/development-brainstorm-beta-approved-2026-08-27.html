Persistent multi-idea Jarvis context

Reconciled revision 3 · active understanding after raw notes + discussion

Decision
Discussion synthesis
Jarvis should remain persistently available at the right side of Brainstorm instead of being embedded inside each reconciled idea. Opening an idea is only a reading action. It must not silently alter the conversational context. When deeper reasoning is desired, the operator explicitly adds one or more ideas to Jarvis context, or requests them naturally in chat by ID. The context basket can combine IDEA records with linked raw notes, relevant past discussions, model/version references, Literature sources and Design/Coding objects. This allows comparisons such as IDEA-030 + IDEA-034 without duplicating chat state across cards. Jarvis may then propose an update to an existing reconciled idea, create a new idea derived from several records, or mark source Raw notes as reconciled/superseded. None of those changes become authoritative until explicitly approved.
Open questions
• Define context-size limits and what gets summarized when the basket becomes large.
• Decide whether a saved context set can be named and reopened later.

Open-source XYZ for local engineering inference

Reconciled revision 4

CODING
Discussion synthesis
XYZ is worth keeping as a candidate local component because it supports private inference, exposes a controllable runtime surface and integrates well with the broader sovereign-AI direction. It is useful for: local reasoning over engineering context, low-cost experimentation, offline operation and bounded agentic tasks. It is not suitable for replacing deterministic engineering validation, canonical state mutation rules, or provider/egress policy. The preferred direction is therefore to integrate XYZ behind the model/provider layer as an optional execution capability, never as the authority deciding whether a model or engineering result is valid.
Still to verify
• Actual Windows/Vulkan stability on the target hardware.
• Tool-call reliability under long context.
