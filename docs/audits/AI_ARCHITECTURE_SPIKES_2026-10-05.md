## CLM-v0.1 — REF-006

**Provenance.** [Contrastive-LM/CLM](https://github.com/Contrastive-LM/CLM), [CLM-v0.1-8B weights](https://huggingface.co/Contrastive-LM/CLM-v0.1-8B), and the `contrastive-lm` package were inspected for the local phase-1 report. The report identifies Apache-2.0 weights and Qwen3-8B base; verify exact upstream revisions and transitive licenses before reuse. Published speed and benchmark claims are vendor results, not Jarvis measurements.

**Mechanism.** A frozen Qwen3-8B encoder embeds the state and each candidate separately; two small projection heads score candidate similarity. Fixed candidate embeddings can be cached. The output is a relative ranking over the offered choices, not a generative action or calibrated permission decision. `backend/app/modules/local_ai/decision_gateway.py` is the existing advisory decision seam. Jarvis's deterministic router, privacy/egress gates, grants, and workspace-action executor must retain final authority.

**Caveats and disposition.** The report estimates roughly 16 GB for the bf16 encoder before co-resident Gemma, exceeding the 12 GB laptop GPU; quantization could alter the trained embedding distribution. No CLM smoke scoring occurred. `CANDIDATE` for a bounded, scheduled benchmark only: compare rules, resident generative routing, and CLM on held-out Jarvis intent/actions; measure refusal/escalation recall, abstention, calibration, cached versus uncached latency and memory. The 72-row decision corpus and prior 51-task/23-Hermes benchmark are seeds, not sufficient labeled evidence for all new decision classes. Reject integration unless quality and end-to-end cost beat the deterministic incumbent without authority widening.

## CopilotKit/OpenDots, CopilotKit/OpenBot, and AG-UI — REF-049/050

**Corrected provenance.** Official [CopilotKit/OpenDots](https://github.com/CopilotKit/OpenDots/tree/c2569bb6a13a22e565cf3eb791c62267d06babb1) was inspected at `c2569bb6`. Its [computer setup](https://github.com/CopilotKit/OpenDots/blob/c2569bb6a13a22e565cf3eb791c62267d06babb1/docs/COMPUTERS.md) and [pinned deployment record](https://github.com/CopilotKit/OpenDots/blob/c2569bb6a13a22e565cf3eb791c62267d06babb1/deployment/computers/README.md) identify a separate official [CopilotKit/OpenBot](https://github.com/CopilotKit/OpenBot/tree/b6932d31a8d6e7896c15139dfc27a6c6911deb27) computer service/supervisor at `b6932d31`. OpenDots builds that exact Git revision and patches the supervisor to derive a per-Dot computer token from a master token. The official repositories state MIT and include an OpenBot license notice; review material transitive licenses before reuse. `meetopenbot/openbot` and `Anil-matcha/open-dots`, inspected in the earlier local report, are **unrelated namesakes**, not the sources of the official product's computer capability. GitHub metadata shows neither OpenDots repository as a fork of the other. The earlier report's claim that public OpenBot lacks a computer was wrong for **CopilotKit/OpenBot** and is withdrawn.

**Verified source mechanisms.** Official OpenDots maps each Dot ID to a container with separate persistent browser profile and workspace volumes. [OpenBot supervisor source](https://github.com/CopilotKit/OpenBot/blob/b6932d31a8d6e7896c15139dfc27a6c6911deb27/supervisor/src/docker.ts) drops capabilities, sets no-new-privileges and a PID limit, permits memory limits and an optional `runsc` runtime, and publishes only a loopback control port in local mode. In container mode the app reaches computers by name without published host ports; only the supervisor has the Docker socket. [OpenDots service code](https://github.com/CopilotKit/OpenDots/blob/c2569bb6a13a22e565cf3eb791c62267d06babb1/src/server/computer-service.ts) checks per-Dot browser/file/shell permissions, refuses unknown actions, audits outcomes, and aborts active requests when permission is revoked. [Audit rows](https://github.com/CopilotKit/OpenDots/blob/c2569bb6a13a22e565cf3eb791c62267d06babb1/src/server/computer-store.ts) persist in SQLite with bounded retention and exclude typed values/full commands. The computer UI and [OpenBot control code](https://github.com/CopilotKit/OpenBot/blob/b6932d31a8d6e7896c15139dfc27a6c6911deb27/agent-computer/src/control.ts) implement human browser takeover and handback with a fresh snapshot requirement. OpenDots also has an approval card before saving a draft page, plus scheduled work and pause/retry; it uses AG-UI for agent/UI events. These are implemented interfaces, while live behavior and durability after failures were not independently rerun here.

**Limits.** Official [computer documentation](https://github.com/CopilotKit/OpenDots/blob/c2569bb6a13a22e565cf3eb791c62267d06babb1/docs/COMPUTERS.md) says its default Docker isolation shares the host kernel, shell can use the container network and read its browser profile, and no restrictive network-egress policy is configured. Per-Dot credentials do not by themselves block outbound traffic. A revoked capability cancels the app request but cannot undo completed side effects; an upstream browser operation may finish. The supervisor owns dynamically created containers/volumes outside ordinary Compose cleanup. OpenDots' draft-save approval is narrower than Jarvis's general typed workspace actions. AG-UI's bidirectional state and draft interrupt semantics cannot own Jarvis state or approval authority.

**Disposition.** `CANDIDATE` as a source for isolated browser/computer UX, human takeover, per-agent credentials, resource limits, and persistent action audit. Jarvis already has a governed Relay sandbox/proxy and revisioned proposed actions (`docs/specs/157-relay-safe-workspace.md`, `166-sidecar-workspace-actions.md`). Borrow patterns only against a concrete browser or cancellation requirement: enforce Jarvis egress/data gates, keep computer output advisory, and apply through Jarvis's action owner. A full OpenDots/OpenBot runtime migration is not justified by this audit. An AG-UI adapter remains `PARKED` until a second client needs it; Jarvis remains the state owner. The unrelated `meetopenbot/openbot` abort registry remains a separate possible cancellation pattern, not evidence about CopilotKit/OpenBot.

## Bonsai ternary 27B — REF-055

**Provenance and measurement boundary.** The maintainer's 2026-10-04 directive requests a Qwen 3.8 27B Bonsai ternary GGUF comparison against Gemma 4 12B IT-QAT on the historical 51-task/23-Hermes benchmark. A local file named `/home/thera/models-ext4/bonsai/Ternary-Bonsai-2-27B-PQ2_0.gguf` has a GGUF header but was only 179,139,220 bytes at inspection, so it is incomplete for a 27B benchmark. Its exact upstream revision, license, digest, and full artifact size are not established here; no quality claim is made. The older Qwen3.8-27B IQ2_M runs under `/home/thera/jarvis-control/work/evidence/pre155/e4/` used a different quantization and an earlier protocol, including an incomplete think-off run, so they are not Bonsai evidence.

**Incumbent and next experiment.** The corrected pre-155 matrix (`/home/thera/jarvis-control/work/evidence/pre155/e4/FINAL-S1-MATRIX.md`) reports Gemma 4 12B QAT Q4_0 with uniform relay repair at 35/51 tasks, 14/23 Hermes, zero malformed, p50/p95 12.4/20.0 seconds, and 7,882 MiB peak VRAM. That report measured a 5-task flip across repeated 51-task runs of another responder, so a small single-run difference is inconclusive. Once the exact complete Bonsai artifact and license are verified, run the same pinned harness, 51 valid fixtures, relay repair, hardware settings, and paired repeats. Record task success, tool-call validity, malformed/post-repair outputs, p50/p95, tokens/s, TTFT, cold load, RAM/VRAM and context fit. Keep Gemma as the measured incumbent unless the new evidence warrants a change; restore its runtime after the isolated GPU window.
