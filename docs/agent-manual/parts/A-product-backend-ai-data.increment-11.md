## FAILURE-MODE NOTES

- `privacy.py` intentionally maps invalid/unrecognized policy-mode strings to `FAST_DEV`; callers must not treat malformed mode text as a fail-closed DISABLED state.
- FAST_DEV smoke-console handling allows non-structural-secret text and classifies most such text as internal. Structural secret regex/markers remain the deterministic guard; this is materially more permissive than the strict smoke-console allowlist path.
- Provider registry environment overrides can change the concrete model but only when the configured value resolves uniquely inside the already-bound provider and route; changing execution class is rejected.
- Enabled external-provider models require concrete pricing, and cache-read input price cannot exceed ordinary input price.
- `context_builder.py` preserves caller block order as priority and drops whole selected blocks rather than truncating content; selected evidence imports the BlueCAD evidence selector, but this file remains the AI context-pack seam rather than engineering-runtime authority.
- `costs.py` pricing is a separate hard-coded estimate registry and character heuristic. It must not be mistaken for provider-registry effective pricing, reservation/settlement, token-flow evidence, or actual billed cost.
- `settings.py` also maps malformed persisted policy-mode values to `FAST_DEV`; this is permissive recovery rather than fail-closed behavior. Its stored `api_spend_month_to_date_usd` is not used as canonical status spend: `project_canonical_ai_status` replaces spend/budget truth with the egress-persistence projection.
- `sensitivity.py` has no implicit safe default for unlabelled ordinary content: without a current label or deterministic floor, effective level is `unknown` and raw content is withheld. Deterministic floors are lower bounds, not permission decisions.
- Approved derivatives are not permanently trusted: source deletion/content-digest drift, policy-version drift, or incompatible S4 ancestry makes them stale/ineligible. Ordinary reads are non-mutating unless explicit revalidation is requested.
- Manual external-context preview accepts only server-backed approved derivatives whose content digest matches persisted content; arbitrary caller blocks are withheld rather than treated as sanitized material.
- `contracts.py` registries overwrite an existing provider/model entry with the same ID rather than rejecting duplicates; uniqueness and stronger binding invariants must therefore come from higher-level canonical registry/configuration code. `AIRequest` permits both prompt and messages to be absent and does not itself enforce privacy/routing policy. `AIResponse.raw_provider_metadata` is unconstrained by this contract, so callers must not assume it is sanitized merely because the response validates.
- `deepseek_provider_smoke.py` uses a fallback display identity (`deepseek` / `deepseek-v4-pro`) when route resolution fails, but dispatch still goes through canonical execution. Event `external_call_attempted` is derived from provider metadata and defaults true when a response exists, so it is diagnostic evidence rather than an independent network-call authority. Empty, >1000-character, >160-output-token, DISABLED-policy, wrong-provider-mode, or privacy-ineligible prompts are blocked before canonical execution.
- `egress_confirmation.py` intentionally exposes patchable core bindings and copies them into the core before execution; tests/callers can therefore alter the budget gate or proposed-record builder through this facade. Expired/revoked tickets with persisted continuation authority take the rejected-continuation cleanup path instead of normal dispatch.
- `egress_policy.py` rejects alternate policy paths, unknown/missing keys, duplicate trigger/operation entries, non-v1 schemas, sampling outside 500..10000 bps, unsupported triggers, and any supported-operation set other than exactly `external_provider_call`; policy parsing is deliberately fail-closed rather than permissive.
- `budget.py` counts active/in-flight reservation projections in addition to completed job usage, preventing obvious concurrent oversubscription at the gate. However its generic monthly-budget exhaustion check uses the `AISettingsRead.api_spend_month_to_date_usd` field before provider-specific usage is queried, so callers must not treat this module alone as canonical settlement/accounting truth. Scaleway token usage deliberately adds legacy/settings counters to routed-job usage and reservations; duplicate accounting across those sources would overstate usage if upstream writers record the same consumption twice.
- `egress_confirmation_core.py` is intentionally fail-closed across persisted-state drift: ticket metadata, consumed packet, reservation binding and response binding/dispatch-state mismatches terminalize as configuration/provider errors instead of dispatching or accepting ambiguous results. Adapter exceptions are recorded with dispatch state `unknown`, not guessed as definitely started/not-started. A consumed continuation rejection requires its persisted pause-attempt identity; missing identity raises rather than fabricating recovery state.
- `egress_authority.py` deliberately treats marker-free raw prompts as S1 only under FAST_DEV; every other policy mode pauses unclassified prompts. Local sanitizer fallback closure is rejected if any provider is network-capable, S4 raw/canonical source material never enters model sanitization, and sanitizer output is rejected if any deterministic sensitivity floor survives. Canonical-source approvals revalidate exact source digests transactionally, while manual-context authority rechecks derivative status/digest/level after preview to fail closed on drift.
- `egress_rejected_continuation.py` refuses missing tickets, non-rejected ticket states, rejected tickets without continuation authority, or flows no longer in `confirmation_required`; it never dispatches. Revocation reason is persisted reason when available, otherwise `ticket_revoked`; expiry is normalized to `ticket_expired`.
- `egress_lifecycle.py` uses compare-and-swap state transitions inside immediate SQLite transactions, so stale ticket/reservation versions fail rather than double-consume. Ticket expiry, continuation-authority drift, packet/policy binding drift, or a hard budget block revoke/expire before reservation creation. Reconciliation deliberately becomes conservative whenever provider usage is missing/unverified/mismatched or pricing has drifted: recorded usage/cost is the maximum defensible bound rather than an optimistic estimate. A pre-network reconciliation rejects any nonzero provider usage.
- `gateway.py` has two materially different execution seams: general `run_task` delegates to canonical execution, while `create_modeling_draft` is legacy fake-provider logic. For project-context tasks, a workspace build exception is passed as a fail-closed `context_build_error`; manual context is budgeted first and can consume the entire workspace-context budget. The modeling-draft fake fallback is only permitted for selected Scaleway budget/paid-AI blocks when `use_fake_provider_when_budget_zero` is enabled; fake completion metadata reports stored settings spend rather than canonical settlement truth.
- `egress_persistence.py` uses `BEGIN IMMEDIATE` to serialize preparation mutations and immutable packet-digest collision checks to reject mismatched reuse. Availability reads are intentionally non-mutating, so stale active/in-flight rows remain counted until a preparation/lifecycle path performs expiry/reconciliation. Stale in-flight timeout recovery trusts `ai_jobs` only when the job is non-queued and has complete `usage_source='actual'`; otherwise it books the reservation upper bound as estimated usage/cost. Global actual spend is `max(ai_settings.api_spend_month_to_date_usd, ai_jobs month sum)` rather than a sum, while Scaleway's legacy token counters are added to routed-job/reservation tokens, so upstream duplicate token recording can conservatively overcount.
- `execution.py` splits network and local authority early: any resolved `requires_network` binding is delegated to `egress_runtime` before local context canonicalization/adapter invocation, while local bindings execute adapters directly. Malformed context, context-budget overflow, missing routes/adapters and provider-gate blocks all create no-execution evidence and terminal ledger rows. Local adapter exceptions terminalize immediately and do not traverse fallback chains; only retryable error responses can advance to a configured fallback. A successful `finish_reason=length` stores S4 protected output and enters local continuation; incomplete continuation binding metadata or continuation failures produce `partial_terminal` rather than pretending completion. Caller-supplied `bindings` disable registry fallback expansion, which is intentional test/injection behavior and must not be mistaken for production fallback coverage.
- `egress_runtime.py` is fail-closed before network dispatch: non-network bindings, absent output ceilings, context-build errors, budget/provider blocks, malformed or unauthorized context, prompt-classification/sanitization failures, unavailable adapters, packet-policy errors, and confirmation-required decisions all persist terminal/paused evidence without invoking an external adapter. Manual context requires a workspace and approved server-backed authority; with active BlueCAD evidence lineage, authority drift becomes a hard deny rather than an ordinary pause. After reservation start, adapter exceptions are conservatively recorded with external dispatch state `unknown`; successful responses claiming `not_started` or any provider/model/usage binding mismatch are rejected. Explicit injected `bindings` suppress registry fallback expansion, while production registry fallback proceeds only on retryable provider responses. Length-limited successful external output enters the dedicated external continuation runtime rather than being falsely terminalized complete.
