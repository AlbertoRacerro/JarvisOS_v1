## Capability facts absorbed from former Area A in this increment

- The provider-neutral contract layer distinguishes provider kind/status/health, task type, privacy class, usage provenance, external-dispatch state, policy mode and normalized provider errors. `AIUsage` enforces `total_tokens == input_tokens + output_tokens`, preventing inconsistent token totals from entering downstream accounting through this contract.
- `AIProviderAdapter` is intentionally narrow (`health`, `list_models`, `complete`, future `stream`), while `ModelRegistry.find_models` filters by capability, task, privacy class and provider. These registries describe/route capability; they do not themselves grant egress authority.
- `costs.py` is a simple estimate/proposal seam, not authoritative billing: it estimates input tokens as `ceil(chars/4)`, assumes a default 1024 output-token ceiling when absent, and uses a small hard-coded route price table. Its escalation proposal explicitly exports the prompt as `outbound_text`, excludes context, and emits a warning for confidential/sensitive-IP hints; authoritative current provider pricing/budget enforcement must therefore come from the newer registry/egress controls already mapped elsewhere.
- Sensitivity classification is fail-closed: deterministic pattern matches can raise the effective floor to S2/S3/S4, but cannot themselves authorize external egress. S2-S4 source labels cannot be downgraded in place; external use requires a reviewed derivative/current source binding.
- Sanitized derivatives are source-digest-bound records with explicit draft/approved/revoked/stale lifecycle. Approval rechecks source freshness and deterministic floors; stale source state blocks approval rather than silently reusing old clearance.
- AI-thread submit idempotency binds `request_id` to a canonical request digest. Reusing the same ID with different semantics is a conflict; a duplicate with identical semantics returns the existing durable interaction instead of spending twice.
- Thread context is rebuilt server-side immediately before reservation and compared to the expected digest. Exact-ref Jarvis context is rejected for non-local routes, and dispatchable Jarvis previews must still match the inspected digest.
- A thread interaction is transactionally reserved with an `ai_flow` before provider execution and transitions through `reserved -> dispatching -> captured/capture_failed`; assistant text is bounded on persistence, so durable thread capture is not confused with provider execution success.
- `egress_persistence.py` atomically persists immutable packet identity plus the policy decision. Hard denials create no reservation; confirmation-triggered attempts create a pending ticket but no reservation; silent allows create one active projected-cost reservation. Packet-digest reuse is accepted only when all immutable packet fields match, otherwise it fails as a collision/mismatch.
- Budget projection counts both actual jobs and active/in-flight reservations. Provider credentials are re-resolved before allowing network-required providers; missing settings, disabled policy/paid AI, zero/exceeded global budget, provider-specific caps/mode, or invalid/missing credentials produce explicit hard-block reason codes.
- Stale `in_flight` reservations are never simply discarded: if actual provider usage is durably available it is recovered; otherwise the projected upper-bound tokens/cost are conservatively charged as estimated usage, an egress attempt is persisted, the AI job is marked provider-error when still queued, and reservation reconciliation uses a versioned CAS to fail on concurrent mutation.
- `execution.py` keeps cloud spend opt-in: omitted routes resolve through task-kind defaults to `local:fake`; a resolved network binding is immediately delegated to the external egress runtime rather than constructing a provider request in the generic/local path. Local execution still records malformed/unbound routes, context failures, missing adapters and provider failures as durable jobs plus token-flow evidence instead of treating no-response paths as absent attempts.
- Local continuation is bounded by persisted flow authority and S4 protected segments. It requires complete binding/output-ceiling metadata; failure to continue terminalizes the assembled partial output explicitly. Proposal/record capture occurs only after a successful `stop` terminal response, avoiding durable project-memory mutation from truncated output.
- `egress_runtime.py` is the mandatory per-binding network boundary. It rechecks budget/provider gate before authorization, authorizes context and prompt before packet construction, and persists prepacket deny/pause outcomes without invoking an adapter. Silent allow must create a reservation; the provider request is then reconstructed from the persisted packet after `start_reserved_attempt`, not from mutable caller input.
- External adapter exceptions are finalized with `dispatch_state=unknown`, while failures before adapter invocation are finalized as `not_started`. Successful/error responses are rejected if provider/model identity differs from the reserved binding or if dispatch evidence is invalid; this prevents a response body alone from proving the intended external execution occurred.
- External fallback advances only after a retryable provider error. A successful length-limited response enters the governed external continuation path instead of silently starting an unrelated request; confirmation-required outcomes transition the flow to an explicit `confirmation_required` state.
