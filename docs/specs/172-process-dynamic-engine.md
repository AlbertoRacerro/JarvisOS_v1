# 172 — Process dynamic engine

State: **accepted and ready**. Hard dependencies 170 and 171 are merged. The [PBR engineering architecture record](../implementation/pbr-engineering-architecture-2026-10-02.md) §§4.1, 5.4–5.5 and row 172 supplies the accepted direction. A read-only independent contract review on 2026-10-05 identified an environmental interpolation/gap ambiguity; the typed temporal rules and fail-closed gap behavior below resolve it. Implementation authority begins only when the corresponding `docs/specs/STATUS.md` readiness transition is merged.

## Outcome

An operator or API client can define a revisioned operating scenario for a Process draft, start a 30-day Tier 1 photobioreactor simulation without blocking the request, follow progress, cancel it, and inspect reproducible time-series and balance evidence. Jarvis owns the scenario clock and state through CVODE. A requested downstream DWSIM balance is sampled quasi-steadily and cannot alter or invalidate the biological trajectory when it fails.

172 is a headless engine slice. The scenario editor, charts, comparison and CSV user interface belong to 173. No scenario starts automatically from an agent proposal or draft edit.

## Authority and input contract

1. `schedules`, `controllers` and `scenarios` are typed content inside the existing Process draft document. Create, update and delete are DraftOps through the existing workspace, draft revision, CAS, undo and proposal rules. Existing documents load without them. Semantic edits invalidate dependent scenario results; layout-only edits retain currentness when all bound inputs are unchanged.
2. A scenario binds an exact draft revision and content digest, selected units, pinned model-card revision and parameter digest, one or more 171 profile `(profile_id, digest)` pairs, initial culture state, UTC start/end, output cadence, event/controller cadence, fidelity `T1`, solver method and tolerances, and optional downstream sampling cadence. The run snapshots these inputs before execution. A profile read verifies its digest. Stale, missing, incompatible, or corrupt inputs fail before the worker starts.
3. The schedule admits typed, bounded time events for inoculation, feed or setpoint change, harvest and dilution; repeated events have a finite count or end time. Simultaneous events have a defined stable order recorded in the artifact. Conditional actions declare an observed state, threshold, direction and hysteresis. Each action has an explicit unit, target and domain check. There is no free-text expression, Python callback, arbitrary URL or provider call.
4. Controllers are typed on/off with hysteresis, PI with bounded output and anti-windup, or turbidostat harvest. Sample cadence and actuator bounds are explicit. A controller may read or actuate only channels the selected model actually exposes. In 172, T1 biomass, nutrient, dissolved O₂, dilution/harvest and declared feed are candidates; CO₂, pH, thermal and Degasser actuators wait for 175. An unsupported measurement or actuator is refused rather than silently treated as an open-loop value.
5. Environmental channels use 171's UTC interval-end semantics. Irradiance and PAR are interval averages: each stamped value is held constant over its preceding interval, with no interpolation across interval boundaries. Point-valued temperature, wind, cloud and wave channels are linearly interpolated between adjacent stamps. The profile must cover the full consumed scenario range, including the point-channel bracketing samples. Any `null` in a consumed interval or bracket blocks the run with the channel and time identified; 172 has no gap-fill or extrapolation policy. Unconsumed channels do not block it. The effective temporal rule and profile resolution are recorded in the snapshot. The worker never fetches live weather or changes the source profile.

## Execution contract

1. Reuse the 103 `integrate_ode`/scikit-sundae CVODE owner and the reviewed 170 T1 equations and cylindrical optics. The 170 periodic steady-state solver may supply an explicitly selected initial condition, but it must not silently replace a transient scenario with a periodic orbit. All participating T1 units advance as one coupled culture-state vector with explicit flow and mixing balances; unsupported unit or recycle coupling is refused before the job starts. CVODE advances that state; no DWSIM dynamic solver or second ODE integrator advances it. Tier 1 remains a lumped-state model, with no hidden residence-time delay or axial profile.
2. Split integration at all schedule, controller, profile interval and output boundaries. Between segments, apply discrete actions once, in the documented order. Record pre/post event states and material transfers so mass, nitrogen and O₂ accounting includes impulses. The integrator's time base is elapsed SI seconds from UTC start; local display time never changes integration or event identity.
3. At every state transition reject nonfinite or materially negative concentrations, out-of-range model-card use, nonphysical transfer, and invalid controller output with a typed diagnosis. Preserve the latest valid segment and mark the job failed; a solver success flag alone is not a physical-validity claim.
4. An optional downstream DWSIM solve sees a snapshot of the Jarvis boundary streams at a macro step and returns conventional steady-state results only. Each call has a timeout and iteration cap. After non-convergence it retries once from a damped tear between the last converged state and the failed attempt. A second failure records `downstream_unconverged`, residual and timestamp; the CVODE trajectory continues. The final manifest distinguishes missing downstream values from zero values. Daily sampling is the default; hourly is an explicit choice. DWSIM cannot own time, biology, culture state or scenario cancellation.
5. Start returns a job id promptly. The workspace-scoped API offers start, status/progress, cancel, list, and bounded artifact/series reads. A job has terminal `succeeded`, `failed` or `cancelled` state, exact input identity and timestamps. Cancellation is checked at segment and DWSIM boundaries; it never publishes a partial run as successful. A process restart cannot leave a job falsely `running`: recover it to a truthful interrupted outcome or safely resume only with an explicit, verified checkpoint. The implementation may reuse an existing job owner; a new generic orchestration service is not part of this contract.
6. Work and storage are bounded before admission: maximum duration, number of output points, events, controllers, active jobs and DWSIM samples are explicit and tested. The accepted baseline is a 30-day T1 run at hourly outputs within the Tier 1 architecture budget of less than one second per simulated day on the qualification host, excluding optional DWSIM. If measured host cost differs, record the result and set a truthful operational limit rather than fabricating budget compliance.

## Results and provenance

An immutable run contains a compact columnar `.npz` time-series file and JSON manifest beneath the `core/paths.py` data root. The manifest binds exact draft, profile, model-card, evaluator and solver versions/digests, channel names and SI units, fidelity and qualification labels, event and controller logs, convergence and validity diagnostics, DWSIM sampling outcomes, and balance residuals. Reads check the artifact digest and enforce workspace scope. A cancelled or failed run retains a clearly labelled diagnostic artifact only if it contains real computed data.

Report at least biomass, dissolved N, dissolved O₂, light and temperature inputs, dilution/feed/harvest, controller outputs, cumulative harvest, and material and nutrient balance terms when the selected model supports them. Compute volumetric and areal productivity and energy per kg only from available, declared inputs; unavailable quantities remain absent with a reason. `T1` and model qualification status are visible to API clients. No scenario output promotes parameters or a model card.

## Required evidence

- DraftOp/API tests for CAS, undo, stale semantics, profile digest tampering, unsupported channels and actuators, event bounds, units, UTC/DST behavior and gap policy.
- Independent T1 transient references: constant-rate and no-light limits; a discontinuous feed/harvest case with hand-computed impulse balances; controller hysteresis and PI saturation/anti-windup; reproducibility across two identical runs. Compare a schedule-free 24-hour scenario with the 170 equations at a declared identical initial condition, without requiring periodic-state identity for arbitrary initial states.
- A 30-day T1 qualification run on the relevant host with measured wall time, output count, state validity, balances, memory and artifact size. Capture exact head, model card, profile and solver identity. Exercise a washout branch and a productive branch.
- Inject a DWSIM timeout and non-convergence at a macro step. Verify one damped retry, a recorded residual and gap, continued CVODE trajectory, and unchanged biological values against the no-DWSIM run. Where available, prove one real DWSIM 10.2.9 downstream sample and a real recycle case.
- Cancel during integration and during a DWSIM boundary; restart after a running job; verify truthful terminal state, no orphan worker or false successful artifact. API polling and bounded series reads must work without a browser.
- Full relevant backend tests and Ruff. No Chromium requirement in this headless slice; 173 carries the visual acceptance.

## Non-goals

No DWSIM-owned dynamic simulation, FMI co-simulation, arbitrary model scripts, live environmental fetch, UI scenario editor or chart, thermal/carbonate/pH physics, gas-transfer unit, 1D loop dynamics, optimization, new provider route, or automatic production use of experimental decision models. 175 and later specs own the absent physics. Existing synchronous Validate/Run retains its current contract.
