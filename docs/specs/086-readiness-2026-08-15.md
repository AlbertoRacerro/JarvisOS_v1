# 086 MODEL-INSPECTION-A0 — readiness decision — 2026-08-15

## Decision

Promote 086 from `planned` to `ready` for one bounded frontend-only implementation of geometry inspection over the existing BLUECAD GLB viewer.

Readiness baseline: `master` `14d3ce9154b66f37e84397020208936126f36a79`, which includes the merged complete definition from PR #242.

Implementation remains unauthorized until this readiness record and the matching `STATUS.md` promotion are merged.

## Frozen purpose

086 adds transient inspection of geometry that is already present in the loaded GLB. It must not invent semantic scene identity, persistent mesh/component IDs, CAD editing, engineering truth, evidence, lineage, or a second selection authority.

Every hit is valid only inside one currently loaded viewer session. Candidate/workspace selection and lifecycle remain owned by 085.

## Exact implementation boundary

Authorized runtime paths are limited to:

- `frontend/src/components/BluecadGlbViewer.tsx`
- `frontend/src/components/bluecad/BluecadWorkbench.tsx`
- optionally one small file under `frontend/src/components/bluecad/` containing pure/session-scoped inspection helpers or a deterministic harness
- `scripts/check_model_inspection.py`
- `docs/specs/STATUS.md` for normal implementation lifecycle transitions

No backend, schema/migration, API route, package manifest, lockfile, workflow, provider, credential, budget, egress, global shell, global visual-identity, 092 scene-binding, 058c scene-semantics, FEM/CFD, lineage, runs, analytics, Jarvis/thread, grade, or editable-CAD change is authorized.

If implementation proves to need any excluded path, stop and re-derive readiness instead of expanding scope silently.

## Frozen interaction contract

A successfully loaded artifact may expose:

1. pointer mesh selection by Three.js raycast against only meshes under the owned loaded-artifact subtree;
2. one keyboard-operable mesh selector/list derived from the same mesh inventory;
3. one compact readout in the existing BLUECAD contextual sidecar;
4. explicit clear-selection behavior;
5. unchanged orbit/pan/zoom behavior.

Pointer inspection must use renderer-canvas-relative coordinates. The selection gesture is frozen as a click release with no material drag since pointer-down; OrbitControls remains authoritative during camera movement. A click that produces no current-artifact mesh hit clears the current geometry inspection.

No helper/grid/light object is inspectable.

## Frozen data contract

Inspection may render only facts derived from the currently loaded Three.js scene:

- artifact object/mesh name when present, otherwise a neutral session-local ordinal label;
- material names when present, explicitly labeled artifact metadata;
- triangle count when calculable from current BufferGeometry;
- world-space axis-aligned bounds;
- neutral session-local mesh ordinal/identifier.

Coordinates/bounds must be unitless unless an existing authoritative artifact contract explicitly supplies a unit. No durable Three.js UUID, traversal index, mesh name, GLTF extras, or viewer-generated key may be represented as JarvisOS semantic identity.

No inspection fact is persisted or sent to the backend.

## Session and stale-response contract

The viewer owns a monotonically replaced inspection session for each successfully loaded artifact instance.

Mesh inventory and current hit are cleared before a new artifact load begins and on:

- `artifactUrl` replacement;
- load failure;
- WebGL startup failure;
- scene disposal;
- component unmount.

Loader callbacks and pointer/keyboard events from any superseded session must fail closed and cannot repopulate inventory, status, or hit state.

React state must store serializable inspection facts/keys, not retain disposed Three.js mesh objects as long-lived inspection state.

Existing 085 cleanup remains mandatory: owned geometries/materials/textures, controls, renderer, ResizeObserver/window listeners and animation frame are disposed exactly once.

## Presentation and accessibility

Inspection is subordinate to canonical candidate information in the existing contextual sidecar. It must include clear copy equivalent to `Geometry-only · current viewer session · no semantic component identity`.

Required behavior:

- keyboard-operable selector with visible focus;
- pointer and keyboard routes feed the same current-session selection;
- canvas accessible label remains accurate and does not imply editing or semantic binding;
- no noisy live announcements during orbit/pan/zoom;
- compact desktop and effective 200% zoom retain a usable viewport and no page-level horizontal overflow;
- system/light/dark and reduced-motion contracts remain inherited from 070/083/085.

## Blocking failure modes

Implementation is not acceptable if any of the following is observed:

1. a stale mesh hit survives artifact replacement, failed load, disposal, or unmount;
2. state retains disposed mesh objects or stale callbacks can mutate the current session;
3. a mesh is presented as a JarvisOS component/record without 092 authority;
4. pointer raycast uses page coordinates or can hit viewer helpers;
5. inspection is pointer-only;
6. orbit/pan/zoom materially causes unintended selection or is degraded;
7. bounds/dimensions claim an invented unit;
8. inspection changes 085 candidate selection or lifecycle state;
9. backend requests/writes are added beyond the existing secure GLB fetch;
10. compact/200%-zoom behavior causes page-level overflow or makes the viewport unusable.

## Deterministic proof

The implementation must add `scripts/check_model_inspection.py` as a dependency-free conformance checker with self-tests. It must at minimum enforce the frozen path/scope boundary, no semantic-identity/backend-write claims, the presence of current-session stale guards, keyboard-equivalent selection, and preservation of 085 viewer/workbench contracts. It is not a substitute for browser behavior proof.

If pure inspection/session helpers are extracted, add a locked TypeScript harness that proves inventory filtering and stale-session acceptance/rejection without requiring a browser.

Required exact-head gates for the implementation PR:

```bash
python scripts/check_spec_status.py --self-test
python scripts/check_ui_foundation.py
python scripts/check_app_shell.py
python scripts/check_bluecad_read_model.py
python scripts/check_bluecad_workbench.py
python scripts/check_model_inspection.py
cd frontend
npm ci
npm run build
```

Browser evidence on the exact implementation head must prove with a real small GLB:

- pointer hit selects a current-artifact mesh with canvas-relative coordinates;
- click-without-material-drag does not conflict with OrbitControls;
- a no-hit click clears inspection;
- keyboard selector reaches the same inventory/state;
- helper/grid objects never appear in inventory or hit results;
- artifact A → B replacement cannot show A inventory/hit after B becomes current;
- load failure clears inventory/hit and does not crash the surrounding 085 workbench;
- resize and effective 200% zoom preserve containment and no page-level horizontal overflow;
- candidate selection/lifecycle and real GLB loading from 085 remain functional;
- no uncaught browser exception occurs in the exercised matrix.

Existing repository CI and BLUECAD Real Tool Proof must also be green on the exact implementation head when triggered by the touched-file set.

## Minimum-necessary decision

No new 3D dependency, backend endpoint, persistence layer, semantic binding manifest, state library, panel framework, or generalized viewer abstraction is needed. Existing Three.js, OrbitControls, GLTFLoader and 085 shell regions are sufficient.

Any proposal to add one of those is rejected by YAGNI unless implementation evidence proves the frozen acceptance criteria cannot be met without it.

Rollback removes the 086 inspection controls/state/hooks/checker-specific implementation and restores the merged 085 `BluecadGlbViewer`/workbench behavior. There is no data migration or backend cleanup.
