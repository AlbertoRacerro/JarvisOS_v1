# DWSIM whole-engine qualification — 2026-09-24

Status: candidate architecture evidence, not a runtime or scientific qualification. This extends the 103 bakeoff after the maintainer clarified that internal commercial use, without software distribution, is the present deployment assumption. It does not supersede accepted 103/104 implementation evidence or authorize a 107 ownership change by itself.

## Decision under test

Evaluate a **complete pinned DWSIM engine** as the owner of generic process streams, thermodynamics, units, flowsheet topology, recycle, steady and dynamic solving, holdup, control and native case files. JarvisOS would retain canonical project/design state, policy, evidence, scientific qualification, studies, AI and promotion. A replaceable adapter would map exact case and solver identity, units, species, settings, object IDs, errors, convergence histories and balance residuals. No DWSIM object or session ID would become canonical Jarvis state.

The previous 103 [bakeoff](103-process-upstream-bakeoff-evidence.md) deferred DWSIM because the runtime was unavailable. That was an environmental limit, not a technical rejection. The [current upstream](https://github.com/DanWBR/dwsim10) is DWSIM 10; the old repository is archived. The [10.2.9 release](https://github.com/DanWBR/dwsim10/releases/tag/v10.2.9), published 2026-09-20, identifies source commit `d113563` and publishes checksums for self-contained Windows and Linux desktop packages and a Linux headless MCP package. This removes the assumption that a separately installed .NET SDK is required to run a distribution; no package has yet been installed here.

This is source inspection, not execution. The current sandbox has no DWSIM, dotnet, Mono, Docker or Podman binary. Upstream's own test report includes five intentionally failing sample flowsheets; that limits any general reliability claim. A single `.dwxmz` case must be saved by Jarvis-controlled headless execution, opened/edited in the native desktop, saved, and rerun headlessly on both Windows and Linux/WSL. Record exact asset hash, property package, units, solver/version/settings, convergence and balance residuals, custom BlueRev unit behavior, dynamic restart/events, and failure diagnostics. A successful round trip establishes interoperability, not physical validation.

The BlueRev-specific delta remains evidence-backed *Nannochloropsis gaditana* biology, nutrients, CO2/O2 transfer, solar/weather/light/optical attenuation, floating transparent PBR and wave/passive mixing, seawater exchange, harvest/replenishment, wet biomass storage and controls. For each model record source, organism/strain, conditions, units, uncertainty, calibration, validity domain, comparison evidence and qualification status. Numerical fixtures are software evidence only. Available, converged and scientifically qualified are separate states.

Internal commercial use is the current deployment assumption. This report makes no legal conclusion about GPLv3. External distribution/conveyance is a future legal and product decision boundary. Pinning, replaceability, reproducibility and Jarvis authority should govern the technical design now.
