## Minimum implementation ownership

The implementation is limited to these owners, with minimum splitting allowed only when tests prove it reduces authority coupling rather than creating another stack:

1. `scripts/repository_delivery.py` — one deterministic shared Git mutation-safety primitive for repository-development lanes. It owns normalized protected/default-branch refusal, remote/ref validation, common sensitive-path baseline, raw Git-history replacement/graft refusal, exact expected-old-ref CAS, replacement-independent fast-forward proof, exact remote-head readback, result classification, and safe Git invocation configuration. Existing 022/079 callers retain their lane-specific policy and credential/orchestration semantics; they may compose stricter restrictions on top of this baseline.
2. `scripts/local_worktree_actuator.py` — the 141 worker core: registered worker/repository/worktree identity, OS-local user-scoped request handling, observer/reviewer/implementer capability admission, worktree lifecycle, bounded named validation profiles, durable local state/audit, local writer lock, Git-administrative-path pre-write refusal, stage/commit, and delegation of every network-mutating Git operation to `repository_delivery.py`.
3. `backend/tests/test_repository_delivery.py` — deterministic shared Git-delivery safety tests over temporary repositories/bare remotes.
4. `backend/tests/test_local_worktree_actuator.py` — worker topology, state, containment, role, persistence, audit, Git-administrative-path and named-profile tests.
5. Existing `scripts/codex_pr_autopush.py`, `scripts/daily_development_continuation.py`, `.github/workflows/daily-development-continuation.yml`, and their existing tests may receive only the smallest compatibility edits required to consume the shared primitive without changing 022/079 accepted semantics. No product backend route, frontend surface, product SQLite migration/store, generic MCP framework, generic process supervisor, PTY, desktop layer, self-update component, or general hostile-code sandbox is authorized.

## Frozen sensitive-path and Git-administrative-path policy for implementation

Readiness freezes one **shared baseline plus lane-specific stricter policy**, not by pretending the existing 022 and 079 classifiers are already identical.

The 141/runtime shared sensitive-path baseline must refuse before stage/commit/push:

- `.github/**`;
- `AGENTS.md` and every recognized `CODEOWNERS` path;
- `scripts/codex_pr_autopush.py`, `scripts/daily_development_continuation.py`, the 141 worker/shared-delivery modules, and the tests that guard those authority boundaries;
- `.env`, `.env.*`, and credential/secret/token/key material using the 022 source-code carve-out so ordinary source files such as `token_counter.py` are not classified as secrets merely by their names.

Separately, before **every actuator filesystem mutation**, not merely stage/commit/push, the worker must resolve the worktree Git administrative entry, per-worktree Git directory, and common Git directory and refuse any target that is or resolves into those locations. This includes the main-worktree `.git/**`, a linked-worktree `.git` pointer file, refs, objects, config, hooks, `info/grafts`, `worktrees`, logs/index/HEAD administrative state, and any symlink/junction/reparse/case-normalization alias into them. Refusal is typed `GIT_ADMIN_PATH_REFUSED` and occurs before target bytes change.

The explicit implementation-time compatibility edit to `.github/workflows/daily-development-continuation.yml` is a ChatGPT repository-maintenance action under this readiness, not an actuator capability and not an exception available to the model/request protocol. 079 may continue to refuse a broader set. 022 may retain its current workflow-bootstrap exception only where its own accepted policy permits it. 141 has **no** model-driven exception for the shared baseline or Git administrative paths.

## First-push, raw-history and atomic expected-head boundary

Readiness does **not** grant remote branch creation in 141 MVP.

`push_branch` is admitted only when the target non-default branch already exists on the approved GitHub HTTPS remote and has a concrete 40-character `expected_remote_head`. An absent remote branch returns typed `REMOTE_BRANCH_ABSENT` with no credentialed push. Creating/publishing a new remote branch remains outside 141 and may use an already-authorized GitHub/control-plane path.

A plain pre-read followed by ordinary `git push` is **not** an atomic compare-and-swap and is therefore insufficient. Before credential admission or network mutation, the shared primitive must also reject synthetic Git history: any `refs/replace/**` entry or legacy `info/grafts` metadata in the verified repository/common Git directory returns typed `GIT_HISTORY_REPLACEMENT_REFUSED` without modifying that metadata. All ancestry, revision-walk and commit-delta checks used for admission/postconditions must run with replacement objects disabled against the verified Git directory/common directory; explicit graft rejection remains mandatory.

The shared primitive must implement this exact sequence:

1. validate the raw-history trust boundary above, then fetch/read the target branch and require its exact SHA to equal `expected_remote_head` before credentialed mutation admission;
2. require the intended local commit to be a descendant of `expected_remote_head` against the unreplaced object graph; otherwise return typed `NON_FAST_FORWARD_REFUSED` without push;
3. perform the network update with an exact target ref and `--force-with-lease=<target-ref>:<expected_remote_head>` used **only as the atomic expected-old-ref equality guard**;
4. expose no generic force flag, no caller-controlled lease value/ref, and no path that can intentionally admit a non-fast-forward update;
5. treat lease rejection as stale-CAS refusal and never retry automatically against a newly observed head;
6. declare success only after a fresh remote reread equals the intended local commit SHA exactly.

This is a narrow transport-level exception to the earlier lexical `force-with-lease` exclusion: 141 still has no force-push authority. Fast-forward ancestry is independently proven against the unreplaced object graph before invoking the lease-CAS push, so the lease cannot authorize rewriting branch history. Any implementation that permits a non-fast-forward update fails readiness.

This supports the first dogfood target (#559), whose PR branch already exists remotely. The optional host activation smoke must seed its disposable remote branch through a non-141 authorized path before exercising the 141 guarded push.

## Named validation profile boundary — no mutable-worktree code execution

The review finding that fixed argv/env/cwd is not a sandbox is accepted. A predeclared command such as `pytest` can execute attacker-controlled/import-hook/worktree code as the maintainer user and thereby bypass reviewer RO, worktree containment, credential boundaries, or subprocess restrictions.

Therefore 141 MVP does **not** execute mutable repository/worktree code through named profiles. The named-profile surface remains only for bounded worker-owned validation operations whose executable and inputs are immutable/trusted worker assets and whose behavior cannot import/execute repository code. A requested profile that would execute, import, source, build, or otherwise run mutable worktree content — including ordinary pytest/npm/build/script profiles — returns typed `LOCAL_TEST_PROFILE_REQUIRES_ISOLATION` with no process launch.

Reviewer role cannot execute mutable worktree code either. Repository tests that require running candidate code remain available through separately governed cloud/CI or a future separately authorized OS-isolation/process capability. This refusal does not make a local worker or its absence a global blocker and does not absorb 126 PTY or invent a sandbox inside 141.

## Local state and Windows credential adapter

The worker state root is OS-user-private and outside registered repositories. MVP layout is the full-spec `worker.json`, atomically replaced `registry.json`, `locks/`, `audit.jsonl`, and an empty trusted hooks directory. The worker must fail closed if permissions/ownership or path identity cannot be proven. State is development-plane evidence only and never STATUS or product authority.

First supported host is **Windows current-user**. Credential acquisition is delegated to an existing **Git Credential Manager** installation used by controlled HTTPS GitHub Git operations. The model/request protocol cannot select or rewrite helpers. Readiness does not authorize GitHub CLI token export, PAT files, SSH keys, a new credential database, or returning helper payloads. If the approved GCM executable/config cannot be identified fail-closed, local push is `LOCAL_CREDENTIAL_UNAVAILABLE` while all non-local lanes remain operational.

Audit remains secret-free. Implementation must include bounded size/rotation behavior: rotate `audit.jsonl` before it exceeds 10 MiB, retain at most five rotated local files, and perform rotation only inside the worker-private state directory. Rotation is local evidence housekeeping and cannot delete repository/GitHub evidence.

## Deterministic test mapping

### `backend/tests/test_local_worktree_actuator.py`

- zero workers online leaves mocked non-local GitHub/CI/review/browser-proof capabilities available;
- one worker offline does not poison another worker/cloud lane;
- wrong-worker dirty/persistent continuation refuses;
- reconnect preserves worktree/local commit metadata and forces remote reread before push admission;
- wrong repository/common-dir/branch/HEAD binding refuses;
- `master`, `main`, configured default/protected branch write paths refuse;
- traversal, symlink and platform-conditional junction/reparse/case-normalization escape refuse;
- every filesystem write refuses the main-worktree `.git` administrative tree before mutation;
- linked-worktree `.git` pointer overwrite refuses before mutation, as do resolved/aliased targets into the per-worktree/common Git directory;
- attempts to mutate Git refs/objects/config/hooks/`info/grafts`/worktrees administrative state leave target bytes unchanged and return `GIT_ADMIN_PATH_REFUSED`;
- reviewer write/stage/commit/push refuses;
- second writer refuses; interrupted writer recovery preserves dirty state;
- unknown named profile and caller-provided argv/env/cwd refuse; no shell/PTTY request surface exists;
- a named profile that would execute/import/source/build mutable worktree code returns `LOCAL_TEST_PROFILE_REQUIRES_ISOLATION` and launches no child process;
- hostile worktree test/import-hook content is never executed by an implementer or reviewer through the 141 profile surface;
- persisted local commit survives requester/session-loss plus worker restart;
- admitted and refused authority-bearing operations both produce reconstructable redacted audit records;
- audit rotation remains inside the private state root and honors the bounded retention contract.

### `backend/tests/test_repository_delivery.py`

- common sensitive paths and protected control tests return `SENSITIVE_PATH_REFUSED` before stage/commit/push;
- pre-existing local commit containing a sensitive delta is independently refused before credential/network mutation;
- source-code secret-name carve-out is deterministic and 079 may layer stricter policy without changing baseline semantics;
- repository/local hooks cannot execute; unapproved credential-helper override refuses;
- URL rewrite, proxy, push-url, SSH command and external filter/process configuration cannot redirect execution/network/credentials;
- unregistered, non-HTTPS or non-GitHub remote refuses;
- child environment is scrubbed and credential sentinel never reaches response/log/audit/error output;
- explicit staged diff produces exact local commit SHA;
- any `refs/replace/**` entry returns `GIT_HISTORY_REPLACEMENT_REFUSED` before credentials/network mutation;
- legacy `info/grafts` returns `GIT_HISTORY_REPLACEMENT_REFUSED` before credentials/network mutation;
- hostile replace/graft fixtures cannot make unrelated commits pass ancestry or sensitive-delta admission; raw graph and metadata remain unchanged;
- ancestry/revision/delta checks are replacement-independent on the verified Git directory/common directory;
- absent remote target returns `REMOTE_BRANCH_ABSENT` with no push;
- stale `expected_remote_head` performs no push;
- race proof: expected=A, remote advances to B, and intended C descends from B still fails because the exact lease expects A;
- intended commit not descending from expected returns `NON_FAST_FORWARD_REFUSED` before push even though the implementation possesses the fixed lease-CAS transport capability;
- generic force, caller-controlled force-with-lease, delete, merge, and default-branch operations are structurally absent/refused;
- successful push is success only after exact remote SHA reread equals intended local commit;
- local/no-op commit is never remote-verified;
- ambiguous result resolves only as full-spec rules permit: intended remote = verified; unchanged expected remote = fresh re-admission required; third-party head = refusal;
- architecture assertion fails if an accepted 141/022/079 path introduces a second ordinary Git push implementation outside the shared primitive.

## LOCAL CAPABILITY ACTIVATION smoke

After repository implementation is merged, optional Windows activation is:

1. start worker as the maintainer's ordinary user;
2. enroll one allowed JarvisOS repository/worktree root through the maintainer-only activation path;
3. prove the approved GCM adapter is available without printing credentials;
4. health + read-only status;
5. seed a disposable remote non-default branch using a non-141 authorized path, attach/create the local worktree, create a local commit, guarded-push against its concrete expected remote SHA, then prove exact post-push SHA;
6. stop the worker and prove non-local GitHub/Actions/review/browser-proof lanes remain unaffected;
7. restart and prove durable metadata plus fresh remote revalidation.

Failure of any host-only step disables only the affected local capability. It is never a global roadmap blocker.

## Minimum-necessary / authority proof

- 141 needs a tiny host-local registry/audit owner because local work must survive requesting-model/product-runtime loss; placing this state in product SQLite would couple an optional development plane to product authority.
- The shared Git mutation primitive prevents a second CAS/push policy stack and preserves environment-specific credentials behind separate adapters.
- Atomic expected-old-ref safety requires a fixed lease-CAS transport, but non-fast-forward authority remains explicitly absent because ancestry is independently proven against the unreplaced object graph and generic/caller-controlled force is unavailable.
- Git administrative state is a separate pre-write refusal boundary; worktree lexical containment never authorizes writes to `.git`, per-worktree Git dirs, or common Git dirs.
- Executing mutable worktree code is not safely bounded by fixed argv/env/cwd, so 141 refuses it rather than inventing unproven process isolation. A later isolation/process capability requires separate authority.
- No dependency on 125 or 126 exists; unrestricted terminal/process and self-update remain unavailable.
- No browser-proof implementation or future spec identity is assumed by 141.
- No second credential store exists: Windows MVP uses OS-owned GCM only.
- With zero local workers, non-local control/evidence lanes remain available by contract and test.

## Readiness result

The bounded implementation above is sufficient to address the observed local-work-loss/delivery failure family without granting broad local-computer authority. Remaining workstation enrollment/GCM proof is explicitly **LOCAL CAPABILITY ACTIVATION** after repository implementation, not a prerequisite for cloud-side Stage 2.

Once this readiness artifact and the matching `STATUS.md: 141 -> ready` transition are accepted on one exact head, implementation may begin. Any need discovered during implementation for arbitrary PTY/filesystem/process authority, execution of mutable worktree code without separately proven isolation, worker self-update, remote desktop, remote branch creation, general credential storage, or product/domain authority invalidates this readiness and requires separate authority.
