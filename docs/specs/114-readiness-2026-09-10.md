## Fresh owner decision

The gap is sufficiently bounded to implement without another architecture checkpoint:

- the frontend route already exists but truthfully renders Literature unavailable because there is no production corpus/read owner;
- the existing files module owns registered artifact identity/path metadata, but fresh master exposes no generic artifact-content serving endpoint; the proven `/bluecad/.../artifacts/{artifact_id}/content` route is BLUECAD-specific and must not be treated as generic Literature authority;
- existing Memory/modeling/project owners already own canonical engineering facts and provenance fields and must not be replaced;
- the missing capability is literature-specific structured provenance plus a bounded read projection, the smallest safe Literature source-content read seam over existing registered artifact identity, and activation of the already-approved UI.

The minimum implementation owner is therefore a narrow `literature` domain module, not a generic knowledge/RAG platform. The source-content seam may factor a reusable path-resolution/read helper under the existing files owner where that is the smallest way to avoid duplicating path-security logic, while Literature-specific content eligibility remains bounded by 114.

## Minimum persistence/API shape

Implementation may rename concrete classes/endpoints, but the semantic shape is frozen:

1. **Literature source identity** — workspace-scoped stable source ID, human title, source kind/state, and an optional validated reference to an existing registered artifact/document. Do not duplicate stored file bytes/path metadata authority.
2. **Literature entry identity** — workspace-scoped claim or datum attached to exactly one source, with bounded statement/value/unit/status fields as applicable and explicit citation locator/context. Non-finite numeric values are rejected.
3. **Stable provenance ref** — each literature entry exposes one deterministic typed ref suitable for existing downstream `source_ref` fields. `used-by` is preferentially a reverse read projection over exact existing provenance refs; do not create a second copy of downstream record bodies or a competing engineering-truth link store merely for convenience.
4. **Bounded reads** — paginated source rows and bounded per-source entries/used-by results. Workspace mismatch, wrong-kind refs, missing artifact, unsupported locator/preview and stale backing data fail visibly.
5. **Curation only** — deterministic operator literature curation/import metadata may mutate this owner; AI/web/research extraction remains proposal-only and is not a baseline external execution lane.
6. **Safe source access** — because no generic content endpoint exists on the re-derivation base, 114 may add only the smallest bounded content-read seam needed for Literature preview/open. It must validate workspace ownership, registered artifact identity, allowed Literature preview MIME/kind, data-root containment and backing-file existence/staleness; it must never expose `stored_path`, arbitrary filesystem access, arbitrary URL fetch, or inherit BLUECAD-only eligibility by accident.

If exact current schema inspection during implementation proves that an existing owner can represent one of these records losslessly, reuse it rather than creating a parallel table. Conversely, do not overload the generic `artifacts` row or opaque `source_ref` string with claim/citation semantics that it does not currently validate.
