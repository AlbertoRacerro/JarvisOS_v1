## Credential status and error contract

Backend `ScalewaySecretStatus` already distinguishes:

- `effective_source`: `environment | secure_persisted | none`
- `persisted_state`: `absent | usable | corrupted | unavailable`
- `storage_mode`: `environment | secure_persisted | none | corrupted | unavailable`
- `key_present`, `source`, optional `last_updated_at`, optional `reason_code`.

`masked_preview` exists in the backend compatibility model but 029 MUST NOT render it and the frontend type should not require/use it. No secret value or derived preview is needed for Settings.

Secret mutation failures already expose safe public FastAPI `detail` objects:

- 400 `scaleway_api_key_invalid`
- 409 `scaleway_api_key_environment_override`
- 503 `scaleway_api_key_persistence_unavailable`
- 500 `scaleway_api_key_persistence_failed`
- 500 delete `scaleway_api_key_delete_failed`

The generic frontend JSON helpers currently discard these bodies and throw only `Request failed with <status>`. The minimum implementation MAY add a narrow typed public API error parser in the frontend client (status + bounded `detail.code` + `detail.message` only). It must never dump arbitrary response bodies, provider payloads, stacks or secrets. No backend error projection is authorized or required.

AI-settings validation errors use FastAPI's bounded 422 validation body. The product surface may present a compact generic validation message and field-local client validation; it need not mirror raw Pydantic structures.

## Read-only Settings projection

The product page may duplicate only the subset useful for operator decisions:

- canonical `/ai/status`: external calls allowed/blocked, blocking reason, provider id/mode, paid-AI state, budget status, credential status, spend and token usage;
- canonical `/ai/settings`: configured budget/caps and direct-continuation limit, plus read-only defaults needed to explain status;
- secret status: effective source + persisted state + storage mode + bounded reason code, never secret preview/value;
- `/system/info`: environment, data-root existence, database configured/ready/initialized, provider configured/calls-enabled summary. Full path maps and absolute database-file details stay legacy-only unless already necessary to explain a concrete failure.

Legacy `/legacy/system-status` and `/legacy/ai-draft` remain reachable. 029 does not delete them.

## State/concurrency contract

Implementation must own asynchronous work explicitly:

- monotonically increasing load generation; stale load completion cannot repaint newer state;
- route departure invalidates ownership;
- independent AI-settings and credential mutation busy locks;
- duplicate click/Enter while a mutation is pending emits zero duplicate writes;
- operator edits are preserved while canonical rereads settle; a stale completion never overwrites newer unsaved input;
- after any successful or uncertain mutation outcome, canonical state is reloaded before further implicit action;
- no automatic retry of PUT/POST/DELETE after timeout/network uncertainty;
- a successful write followed by failed reread is displayed as `state uncertain — reload required`, not optimistic success/failure.

No mutation may call an AI task, provider smoke endpoint, external provider, tool, or egress path.
