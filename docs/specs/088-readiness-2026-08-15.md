# 088 RUNS-WORKBENCH-1 — readiness decision — 2026-08-15

Readiness baseline: `f18318fa4cd154fb1deb3b1ceb8cd0fa6ce24c7a` (merge of definition PR #254).

## Decision

088 is implementable as one bounded frontend-only slice over the already-merged runner/modeling authority. Runtime implementation remains unauthorized until this readiness record and the matching `docs/specs/STATUS.md` promotion to `ready` are merged.

The minimum-necessary product is a read-first operator workbench at the existing `/runs` route. It uses the App-owned transient workspace seam established by 087, reads persisted run truth, and does not migrate scenario creation/execution, add polling, invent progress, add analytics, or introduce a second workspace state authority.

## Exact runtime authority

Implementation must derive TypeScript types from exact runtime models on this baseline.

Existing reads are sufficient; no backend addition is authorized:

- `GET /workspaces` for workspace discovery only;
- `GET /workspaces/{workspace_id}/simulation-runs` for run navigation;
- `GET /workspaces/{workspace_id}/simulation-runs/{simulation_run_id}` for canonical selected-run detail;
- `GET /workspaces/{workspace_id}/simulation-runs/{simulation_run_id}/logs` for persisted runner logs;
- `GET /workspaces/{workspace_id}/simulation-runs/{simulation_run_id}/artifacts` for persisted artifact metadata.

`SimulationRunRead`/`SimulationRunDetail.status` remains a string at this boundary. The frontend must display the persisted value textually and treat unknown values neutrally; it must not coerce historical/manual status strings into the current runner enum.

The modeling list is already ordered by `created_at DESC`. The UI uses that response order and applies `id` only as a deterministic tie-break if needed locally. Runner logs are already returned in `created_at ASC` order.

Artifact metadata may expose normal operator-safe fields such as filename, role/type, status, size, MIME type, digest, source reference/module, creation time, and `under_data_root`. `stored_path` must never be rendered. `relative_path` is not an actionable filesystem link. No artifact-open/download control is authorized in 088 because no additional serving behavior is required to satisfy the accepted slice.

## Binding/results interpretation

The canonical queue calls for runs, bindings, results, logs, and artifacts. 088 satisfies the binding/results part through the persisted run record itself:

- `input_payload` is the persisted executed input evidence;
- `parameter_payload` is the persisted parameter/binding evidence;
- `output_payload` is the persisted result evidence.

088 does not call the 071 side-effect-free pre-run binding/DOF preview for a historical run because that would recompute a present-time preview and could be mistaken for the exact bindings that produced the persisted run. The legacy Domain Foundation remains the creation/preview surface. `/runs` labels these sections `Inputs`, `Bindings`, and `Results` and shows only persisted run evidence.

No unit inference, pass/fail inference, requirement evaluation, freshness claim, comparison, or analytics is added.

## App and workspace ownership

`frontend/src/App.tsx` remains the single owner of transient `workspaceId`.

Runs receives:

- `workspaceId: string | null`;
- `onWorkspaceChange(next: string | null): void`.

The page may call the existing `listWorkspaces()` only to populate its bounded workspace selector and validate the current shell workspace.

Rules:

- preserve a current workspace when it appears in successful discovery;
- when the shell has no valid current workspace and discovery returns rows, request the first response row deterministically;
- zero workspaces and workspace-discovery failure are distinct states;
- changing workspace synchronously clears prior run list, selection, detail, logs, and artifacts before the next workspace read;
- no localStorage, URL/hash/query state, new context provider, global store, or page-owned duplicate workspace authority.

## Run selection and filters

The run list remains read-only.

Allowed local controls:

- case-insensitive search over returned run label and id;
- exact persisted-status filter;
- explicit `All statuses` reset;
- manual refresh.

Selection rules are frozen as follows:

- successful non-empty initial list selects the first returned run when no valid selection exists;
- refresh preserves the selected id while it remains present;
- when the selected run actually disappears from a refreshed list, select the first remaining run or null when empty;
- filtering does **not** change the underlying selected run. If the selected row is hidden, retain its detail and render `Selected run hidden by current filter`; focus stays on the filter control that caused the change;
- clearing the filter reveals the same selection if it still exists.

If refresh removes the currently focused run row, focus moves to the replacement selected row when one exists, otherwise to the stable run-list heading/control.

## Request-race contract

Workspace, list, detail, logs, and artifact reads require monotonically increasing generations plus initiating identities.

A response is accepted only when the current generation and identity match the request context.

Required rejected stale cases:

- workspace A → B → A;
- run X → Y → X;
- late old-workspace list failure after the current workspace succeeds;
- late old-run detail/log/artifact success or failure after another run is selected.

Comparing values captured in an async React closure is not sufficient. One small pure helper may own generation/context acceptance and deterministic selection logic.

## Payload rendering bounds

The persisted input/binding/result strings may contain JSON. They are rendered as inert evidence only.

The minimum bounded representation is a preformatted JSON projection produced by a pure helper, not a generalized tree-view framework.

Frozen presentation limits:

- maximum nesting depth: 4;
- maximum object keys or array items rendered at each container: 50;
- maximum individual string length: 2,000 characters;
- maximum total rendered serialized characters per payload section: 20,000.

When any limit is reached, the rendered representation contains an explicit truncation marker. No HTML, Markdown, links, ANSI, code, expression, or script execution is permitted.

Null payload: normal `No persisted …` state.

Malformed JSON: `Payload unavailable / malformed` with a bounded diagnostic; never dump the full raw string as a fallback.

This bounded projection is intentionally simple and removable. No JSON editor, syntax framework, recursive component library, or new package is justified.

## Logs

Logs are subordinate evidence and load independently from run detail.

- render content as inert text;
- preserve textual stream identity;
- expose `truncated` explicitly;
- no live tailing or polling;
- empty list is `No persisted logs`;
- request failure is a logs-only error with retry and does not clear valid run detail;
- long lines/tokens remain contained inside the technical region and may scroll locally if wrapping would destroy readability.

## Artifacts

Artifacts load independently from run detail.

- empty list is `No persisted artifacts`;
- request failure is an artifacts-only error with retry;
- show only the safe metadata frozen above;
- never show `stored_path`;
- do not create filesystem links from `relative_path`;
- `under_data_root=false` is shown textually without exposing location;
- artifact status never changes or explains run status.

## Status semantics

Persisted run status is text authority only.

Forbidden derived UI:

- percent progress;
- ETA;
- health/confidence/severity score;
- treating absent `completed_at` as proof of `running`;
- treating absent logs/artifacts as run failure;
- guessing model name from id;
- freshness labels without an authoritative later join.

Known current runner statuses may use existing semantic status tones, but text remains primary and any unknown string uses neutral presentation.

No backend, schema, migration, package manifest, lockfile, workflow, provider, credential, budget, egress, global visual-identity token, stage taxonomy, or runner mutation path is authorized.

A dedicated `frontend/src/api/runs.ts` is smaller and safer than expanding the already broad legacy `api/client.ts`; it avoids changing Domain Foundation contracts while giving 088 strict detail/log/artifact types.

A dedicated `runs.css` is independently removable and avoids turning `shell.css` into page-specific ownership. No new CSS processor or component system is introduced.
