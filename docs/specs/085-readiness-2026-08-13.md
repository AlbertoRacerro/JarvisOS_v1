## Re-audit of current runtime

The current runtime still compatibility-mounts `pages/BlueCAD.tsx` from `ModelStage.tsx`. The legacy page owns workspace/candidate discovery, selection, create, archive, duplicate-brief, promotion, validation-report loading, attempt history and real GLB embedding. The 084 aggregate client already exists and is not yet consumed by the page.

`PrimaryStageProps` already exposes the accepted `StageSelection` seam and includes `bluecad-candidate` as a typed `RecordRef` resource. No URL-owned candidate subject seam is required for 085; candidate identity therefore remains stage-local while the selected candidate is published through `onSelectionChange`.

The 083 shell exposes navigator, sidecar and dock containers, but today those containers own fixed generic content and have no stage-content injection seam. 085 may add one minimal presentation-only shell-region contribution contract so Model stage can populate these already-existing regions. This is not a new engineering state store and must not persist server data outside the BLUECAD workbench owner.

## Frozen composition decision

085 uses one BLUECAD workbench owner component under Model stage. That owner is the only place that owns BLUECAD discovery/detail request state, mutation state, archived visibility, local candidate filter text, validation-report detail and request-generation guards.

The owner supplies presentation nodes to the existing shell regions through a minimal additive shell contribution seam:

- contextual navigator: workspace selector, archived/filter controls and candidate list;
- primary stage: compact candidate/action strip plus dominant real GLB viewport;
- contextual sidecar: lifecycle, freshness, validation/evidence/artifact/diagnostic detail;
- analysis dock: ordered attempts and explicit aggregate-linked evidence/run references.

Shell containers remain responsible for open/close/focus/Escape behavior. BLUECAD region children must not duplicate those responsibilities.

No second router, global state library, backend endpoint, schema, cache or scene identity is authorized.

## Request and selection rules

1. Workspace list and candidate list remain discovery APIs.
2. Candidate selection loads exactly one 084 aggregate for visible detail.
3. Every workspace/candidate detail request carries a monotonically increasing request generation or equivalent abort guard; stale responses cannot update visible state.
4. Candidate selection publishes `{ kind: "record", ref: { resource: "bluecad-candidate", workspaceId, recordId } }`.
5. Workspace change, archive, archived-filter change or missing aggregate must revalidate selection deterministically.
6. Mutation success is claimed only after backend confirmation and canonical reload.
7. Create selects the returned candidate after reload; duplicate-brief only copies brief text into the creation form; archive hides/reselects deterministically when archived rows are hidden; promote remains limited to canonical valid/unpromoted candidates.
8. A response belonging to a previous workspace/selection must never mutate the current workbench.

## Data authority rules

Visible detail consumes the 084 aggregate for candidate, artifacts, evidence, runs, freshness and diagnostics. TypeScript must not reconstruct evidence, provenance, run association or freshness joins.

Detailed validation checks may still come from the canonical validation-report artifact because 084 intentionally does not reinterpret report JSON as evidence. Missing or malformed report content is a local validation-detail failure only and must not hide otherwise valid candidate/GLB/aggregate data.

The GLB viewer continues to receive only the secure backend artifact-content URL. `stored_path`, data-root paths and direct filesystem access are forbidden.

Lifecycle, freshness, validation and promotion are distinct concepts and must be rendered separately.

## Viewer decision

`BluecadGlbViewer` remains the real renderer. 085 may change it only if needed for native embedding containment, artifact-change cleanup, loading/error presentation or accessible labeling. No measurement, isolate/hide, clipping, persistent object identity, semantic hit mapping or binding manifest is authorized; those belong to 086/092.

## Checker and deterministic proof

Add dependency-free `scripts/check_bluecad_workbench.py` with a self-test. It must fail if:

- `ModelStage` still compatibility-mounts the old stacked page as the primary composition;
- visible workbench code does not consume `getBluecadCandidateAggregate`;
- client-side freshness/evidence/run authority is reconstructed;
- direct filesystem/data-root/provider access appears in 085 UI code;
- mock workstation values or fake AI/FEM/health/confidence telemetry are introduced;
- forbidden files or dependency/workflow/schema/global-identity surfaces change;
- candidate selection does not use the typed BLUECAD `RecordRef` seam.

Deterministic test/harness coverage must include at minimum:

- workspace change with an older list/detail response arriving late;
- candidate A detail response arriving after candidate B becomes selected;
- archived-filter hiding the selected candidate;
- archive and promote pending-state conflict prevention;
- duplicate-brief semantics;
- aggregate 404/partial diagnostics;
- no GLB and GLB load failure;
- no validation report and malformed validation report;
- zero attempts;
- lifecycle/freshness/validation/promotion displayed independently.

## Accessibility and layout proof

Implementation evidence must prove:

- candidate rows are keyboard reachable and expose selected state;
- critical actions are reachable without pointer-only interaction;
- busy/disabled mutation state is accessible;
- shell navigator/sidecar/dock retain focus-return and Escape behavior;
- GLB canvas has accessible labeling plus adjacent textual state;
- viewer does not trap focus;
- state meaning is not color-only;
- reduced motion remains respected;
- compact desktop and 200% zoom have no page-level horizontal overflow and leave a usable primary viewport.

085 must express that direction using existing 070 semantic contracts and bounded BLUECAD-local styling. It must not canonize global font, palette, iconography, shared-component grammar, radii, shadows or motion. Those remain the independently removable visual-identity lane.

No fake Sketch/Extrude/Fillet tools, AI confidence, health percentages, stress values, FEM jobs, analytics or Jarvis chat may be copied from the reference.
