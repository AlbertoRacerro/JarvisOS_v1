## 1. Decision

071b is implementable from the exact current runtime without a second engineering store, without reopening merged 071 numerical authority, and without inventing scene/model/formula semantics.

The current frontend already has the essential 071 seams: model implementations with versioned input contracts, `previewModelBindings`, normalized ready input sets, runner-job creation and execution. Merged 096 already provides the bounded Jarvis-over-Properties sidecar. The implementation may therefore migrate the existing scenario editing behavior into the Properties region and add transient working-state/race protection rather than creating a parallel modeling system.

One failure mode prevents an unconditional no-backend-change readiness: current `POST /workspaces/{workspace_id}/runner-jobs` creates a persisted simulation run immediately and returns the generated runner-job/run IDs, but the create request has no caller idempotency key and there is no caller-key read-back route. If the POST commits server-side and the response is lost, the client cannot prove whether a run was created and cannot safely retry without risking a duplicate. 071b explicitly requires uncertain dispatch to fail closed rather than blind duplicate dispatch. A minimal server-owned idempotent create seam is therefore authorized below. This is not a new execution subsystem.

No other backend expansion is authorized by this readiness decision.

## 2. Exact runtime evidence

### 2.2 Existing scenario/editor state

This is the behavior to reuse/extract, not a second scenario system. The current implementation lacks revision-safe preview response rejection and a proper working-baseline/dirty/Undo/Revert model; those are 071b work.

### 2.3 Frontend API authority

`frontend/src/api/client.ts` already exposes:

- `listModelImplementations(workspaceId)`;
- `previewModelBindings(workspaceId, modelVersionId, bindings)`;

- `createRunnerJob(workspaceId, payload)`;
- runner execution/read models including persisted `simulation_run` detail and status.

No new frontend provider/model API is required.

### 2.4 Backend input-contract authority

`backend/app/modules/runner/input_contracts.py` is authoritative for preview semantics.

Current contracts expose:

- stable `name`, human `label`, exact `unit`, `required`, category and description;
- optional numeric domain metadata;
- schema-v2 `physical_dimension` and optional `semantic_basis` server-side;
- exact contract digest/canonicalization;
- missing/manual/parameter/invalid binding state;
- required-only structural/bound/unresolved DOF;
- optional missing fields do not increase unresolved required DOF;
- `normalized_input_set` is emitted only when preview is `ready`.

This is sufficient for contract-driven rows, exact units, required-vs-optional `Empty`, basic semantic source labels and deterministic blocker state. It is **not** sufficient to infer the final Geometry/Hydraulics/Thermal/Optical/Fouling taxonomy, mutually exclusive model alternatives, or formula/equation Inspect content. Those remain deferred to 058c exactly as the definition requires.

### 2.5 Runner authority and the one readiness gap

`backend/app/modules/runner/routes.py` exposes:

- model-implementation list;
- binding preview;
- runner-job create;
- runner-job run;
- simulation-run detail/log/artifact reads.

`backend/app/modules/runner/service.py::create_runner_job` generates `simulation_run_id` and `runner_job_id`, validates the implementation/input, persists a `queued` simulation run plus runner job, and then returns the records. `RunnerJobCreate` currently contains model version, run label, input set and timeout only.

Failure mode: response loss after commit has no caller-stable reconciliation key. UI-only button disabling prevents ordinary double clicks but cannot solve transport uncertainty. Therefore runtime implementation must add the minimal idempotency contract in section 7.

## 3. Answers to definition readiness questions

1. **Properties owner:** `frontend/src/components/shell/ContextualSidecar.tsx`; use its existing `propertiesContent` seam.
2. **Reuse existing scenario state:** yes. Extract/recompose the scenario editing/preview behavior from `DomainFoundation.tsx`; do not keep two independently editable scenario states.
3. **Input-contract/preview client:** existing types/functions in `frontend/src/api/client.ts` and backend `runner/input_contracts.py` / `runner/routes.py`.
4. **Effective binding reconstruction:** current preview variables return value, source parameter ID, exact unit, required/category/description and binding state. This is enough for `Manual/Working override` vs `Parameter` and truthful `Empty`; richer provenance labels may be rendered only when explicit existing record authority supports them.
5. **Runner start/idempotency:** current create+run sequence is valid for definite responses, but create has no transport-safe idempotency. Add one bounded caller request key; details in section 7.
6. **Real execution failure vs preflight rejection:** preflight uses binding preview and creates no run. A runner job exists only after successful create; post-create execution statuses include queued/running/succeeded/failed/cancelled/timed_out and persist as simulation-run evidence.
7. **Latest successful run as initial baseline:** **deferred**. Current API has run reads/history, but there is no narrow, already-proven API contract that selects the latest successful run for the exact model-contract digest and reconstructs its binding provenance without client inference. 071b v1 starts from current bindings/session values or `Empty`. Loading a prior run is left to 006b unless implementation inspection finds a truly existing exact compatible read without widening scope.
8. **Optional inputs:** server preview models `required: bool` and excludes missing optional inputs from unresolved required DOF. UI must render optional `Empty` neutrally. Runtime tests must prove any executable optional-contract fixture accepted by the chosen runner path; do not fabricate optional semantics in a model that has none.
9. **Model-choice/sub-contract metadata:** current general contract has no authoritative mutually-exclusive alternative schema. **No model-choice selector in 071b product runtime.** Preserve the component/state seam; 058c owns the actual semantic model-choice contract.
10. **Formula metadata:** current general input contract has labels/domain metadata but no authoritative formula/dependency expression contract for Properties. **No production `fx` formula inspector in 071b.** 058c owns it.
11. **Minimal implementation files:** frozen in section 6.
12. **Browser/read-back proof:** frozen in section 9.
13. **Migration:** one narrow additive runner-create idempotency migration is authorized only if needed to make the caller key durable/unique; no working-configuration persistence migration.
14. **Rollback:** remove 071b Properties integration and idempotency caller use; existing 096 fallback, model contracts, Parameters and run evidence remain valid. Additive idempotency column/index may remain harmless or be removed by a separately verified rollback migration.
15. **Collision:** at readiness start no other open runtime PR owns the 071b surfaces; old 092 remains unauthorized.

## 4. Working-state implementation boundary

The implementation must create one transient working-configuration owner for the selected eligible model contract. Prefer a focused hook/component-local module; do not add Redux/Zustand/a new persistence service.

It owns:

- baseline bindings;
- current working bindings;
- dirty comparison;
- bounded undo stack;
- monotonically changing revision/generation;
- current preview generation/state;
- current run-start state.

Changing model implementation replaces the contract/baseline and invalidates all outstanding preview generations. A preview response is accepted only when model ID + contract digest/request generation + working revision still match the request that produced it.

Version 1 remains memory-only. No `localStorage`, `sessionStorage`, URL persistence or new draft table.

## 5. Initial baseline frozen for v1

Use only values that are already unambiguously present in the active current scenario/binding authority:

1. compatible selected Parameter binding/value;
2. explicit current manual binding in the active session;
3. otherwise `Empty`.

Do not query/guess a previous successful run as an automatic initial baseline in 071b v1.

The baseline label may therefore be `Current bindings` / equivalent. A run that succeeds during the current unchanged working revision may become the new in-memory baseline for that session.

## 7. Bounded run-create idempotency contract

Implement the minimum transport-safe contract, reusing repository idempotency conventions if any exist on exact implementation head.

Required semantics:

- client generates one opaque `request_key` for one intended run creation and retains it across retry of the uncertain POST;
- server scopes uniqueness at least by workspace + request key;
- first valid create persists exactly one simulation run/runner job and the request key atomically;
- retry with the same key and semantically identical create payload returns the same created runner job/simulation run, not a duplicate;
- same key with materially different model/input/run payload fails closed with a stable conflict error;
- no key is reused for a later distinct operator Run;
- the key is machine/audit identity, never primary UI content;
- no provider call, distributed queue or new generic idempotency framework is introduced.

A dedicated GET-by-key route is optional if POST retry with the same key is sufficient to reconcile uncertainty. Prefer the smaller contract.

The server, not the frontend, owns uniqueness. Frontend disabling still prevents ordinary double-click submission; the idempotency key covers response-loss/retry uncertainty.

## 9. Required browser acceptance on immutable implementation head

Use a real product build/backend and prove at minimum:

1. desktop keeps Jarvis above and Properties below with independent local scrolling;
2. 200%/compact mode keeps usable `Jarvis | Properties` tabs;
3. selecting an eligible model contract renders every contract variable exactly once with server label/unit/category meaning;
4. no UUID/hash dominates L0; contract digest/machine IDs remain Technical details;
5. manual edit changes only transient working state and visibly marks dirty;
6. Parameter-backed row remains source-linked; working override does not mutate source Parameter;
7. required missing input shows `Empty` + blocker; optional missing input is neutral where an authoritative optional variable fixture exists;
8. `Go to first issue` focuses/navigates to the first actual blocking row;
9. valid edit causes a fresh preview and compact `Ready`; a stale old preview cannot overwrite it after a newer edit;
10. preview transport/parse failure shows uncertainty and disables new Run;
11. repeated Run clicks while non-ready create zero simulation runs;
12. ready Run sends the exact preview `normalized_input_set`;
13. deliberate duplicate click/in-flight submit creates at most one run;
14. simulated response loss after runner-job create, followed by retry with the same request key, resolves to the same persisted run/job;
15. same request key with changed payload is rejected, not aliased;
16. genuine post-start runner failure remains persisted/visible and working edits remain;
17. successful run does not mutate/promote source Parameters and clears dirty only if the working revision has not changed since start;
18. edit during an in-flight run is not overwritten by completion of that older run;
19. Undo and Revert all restore the current baseline;
20. long labels/source names/values do not create page-level horizontal overflow;
21. keyboard focus, Escape/sidecar focus return, reduced-motion and light/dark/system behavior remain intact;
22. no frontend/provider call and no hidden default/AI-filled value is introduced.

## 10. Required deterministic verification

Add focused tests/checkers proving:

- contract-driven row generation, not a hard-coded BlueRev property list;
- exact units and no implicit conversion;
- preview generation/revision stale-response rejection;
- missing required vs optional state;
- Parameter source remains unchanged after working override and after successful run;
- dirty/Undo/Revert semantics;
- non-ready attempts create zero runs;
- idempotent create same-key same-payload identity;
- same-key different-payload conflict;
- genuine execution failure persistence;
- successful completion cannot overwrite newer working edits;
- legacy 071 tests and merged 096 layout/browser proofs remain green.

Do not add brittle tests that merely search for UI strings while bypassing state behavior.
