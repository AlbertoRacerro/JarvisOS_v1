## Dependency and concurrency audit

Registry dependencies 006, 044, 050, 051 and 083 are merged. No implementation PR is open and no runtime front overlaps BLUECAD candidate reads, evidence, flowsheet provenance/freshness, or the typed frontend client. Penpot visual identity remains separate and excluded.

## Current authority confirmed

- `backend/app/modules/bluecad/ledger.py` owns candidate/attempt ledger reads but its public helpers open separate connections; 084 therefore needs bounded connection-accepting read helpers so the aggregate can remain inside one read snapshot.
- `backend/app/modules/bluecad/evidence.py` owns canonical BLUECAD evidence rows and already supports caller-owned SQLite connections. A candidate/attempt-scoped selector belongs there rather than in BLUECAD-specific cross-domain SQL.
- `backend/app/modules/flowsheet/service.py` owns the closed `<kind>:<id>` resolver and exposes `resolve_flowsheet_node_from_connection()` and `build_flowsheet_graph_from_connection()` for caller-owned coherent snapshots.
- `backend/app/modules/flowsheet/freshness.py` owns stale state. Its current public node lookup opens a new connection, so 084 may add one read-only `get_node_freshness_from_connection()` helper and keep the existing wrapper behavior unchanged.
- `artifacts` metadata is already read by BLUECAD ledger/routes. The aggregate may batch-select only explicitly referenced artifact IDs in the candidate workspace and must never serialize `stored_path`.
- `frontend/src/api/client.ts` is the only authorized frontend change and currently centralizes HTTP behavior.

## Frozen implementation contract

Endpoint:

```text
GET /workspaces/{workspace_id}/bluecad/candidates/{candidate_id}/aggregate
```

Response models are frozen as:

- `BluecadArtifactRefRead`: `id`, sorted lossless `roles`, `filename`, `mime_type`, `sha256`, `status`, `source_ref`, `created_at`, `content_url`;
- `BluecadEvidenceRefRead`: `ref`, `kind`, `subject_ref`, `status`, `stale`, `created_at`, `summary`;
- `BluecadRunRefRead`: `ref`, `kind`, `status`, `stale`, `created_at`, `source_ref`;
- `BluecadReadDiagnostic`: one of `missing_reference`, `malformed_reference`, `inaccessible_reference`, `unsupported_reference`, plus `source`, `reference`, `message`;
- `BluecadCandidateAggregateRead`: canonical `candidate`, `artifacts`, `evidence`, `runs`, four-state `freshness`, and `diagnostics`.

Stable ordering is mandatory:

1. candidate attempts by `(attempt_no, id)`;
2. artifacts by `(id, roles)` with roles sorted lexically;
3. evidence by `(ref, subject_ref)`;
4. runs by `(ref, source_ref or "")`;
5. diagnostics by `(source, reference, code, message)`.

Duplicate artifact IDs appear once with all explicit roles preserved. No timestamp, filename, brief-text or workspace-membership heuristic may create evidence/run associations.

## Accepted reference paths

- Artifact references come only from the six explicit candidate/attempt fields named by the specification.
- Candidate evidence comes only from canonical `evidence_records.candidate_id` or `attempt_id` relationships for this candidate and its attempts.
- Run/model links come only from accepted flowsheet graph edges and canonical refs reachable from `bluecad_candidate:<id>` or its `bluecad_attempt:<id>` nodes. Supported returned run kinds are `simulation_run` and `runner_job`; unresolved graph references become diagnostics.
- Freshness is read only through 051 marks for resolved aggregate evidence/run refs. Missing or unsupported refs remain diagnostics and do not become stale.

## Coherent snapshot and query boundary

The aggregate opens one SQLite connection, enables `PRAGMA query_only = ON`, begins one read transaction, and rolls back on exit. Candidate/attempt, artifact, evidence, flowsheet and freshness reads all reuse that connection. Artifact metadata is one batched query. Evidence is one bounded selector. The graph/freshness owner helpers operate on the same connection. No per-attempt connection or query loop is permitted.

## Test and checker decision

A dependency-free checker is minimum necessary because runtime tests alone do not reliably prove the exact file boundary, absence of UI consumption, absence of schema/workflow/package edits, strict route/client presence, and no forbidden `stored_path` field in response models. The checker must self-test positive and negative fixtures and remain specific to 084.

Implementation gates:


No schema migration, durable projection, cache, package dependency, workflow, browser framework or UI migration is needed. The accepted implementation is one request-time read model plus typed client support. Implementation remains separate from spec 085.
