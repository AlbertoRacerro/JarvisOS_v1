# Spec 094 readiness decision — 2026-08-04

## Decision

Spec 094 — SCALEWAY-NORMAL-SPINE-0 is promoted from `planned` to `ready` after this definition and readiness decision merge into `master` and the registry records the authorized position between blocked 082 and 070.

This decision authorizes one bounded implementation of `docs/specs/094-scaleway-normal-spine-0.md`. It does not authorize implementation on the closed PR #219 branch, a second paid Scaleway dispatch path, a new ledger or schema, frontend work, provider fallback, model promotion, changes to the 082 credential store, or any work from spec 070 onward.

- the required Windows checkpoint includes one bounded external call through `run_ai_task`;

- spec 082 acceptance criterion 26 forbids route-authority changes.

Spec 081 explicitly permits a later definition-only authority slice when an active slice proves non-implementable within its accepted boundary, provided the stop reason and reached state are recorded and the rest of the queue is preserved. 094 is that slice.

## Binding decision 1 — one paid dispatch spine

Every live Scaleway call uses `run_ai_task` and the existing 059b execution boundary.

The implementation adds one no-fallback route, `external:scaleway`, and converts the existing live smoke and smoke-console endpoints into compatibility wrappers over the shared execution service. The wrappers may preserve their current input/output shapes, harmless bounded cases, privacy checks and operator switches, but they may not call the adapter or transport directly and may not create an independent reservation or paid-call ledger.

Synthetic smoke behavior remains local and unchanged.

## Binding decision 2 — route and adapter identity

The route binds uniquely to provider `scaleway` and the explicitly registered model `gemma-4-26b-a4b-it`.

The existing provider-specific `ScalewayProviderAdapter` remains authoritative for transport, `SCALEWAY_BASE_URL`, effective credential resolution and sanitized provider metadata. Registry adapter construction must not replace it with the generic OpenAI-compatible adapter.

`external:cheap`, `external:reasoning` and their fallback chains remain unchanged.

## Binding decision 3 — model controls

The normal route model comes from the validated provider registry.

Legacy `SCALEWAY_MODEL` is isolated to the compatibility smoke surface and cannot participate in global route resolution. A legacy value may be accepted only when it identifies a model already registered for provider `scaleway`; otherwise the wrapper blocks before dispatch without affecting unrelated routes.

Any normal-route environment override must use a distinct route-specific name, resolve to a registered Scaleway model assigned to `external:scaleway`, and fail closed before packet preparation or transport.

## Binding decision 4 — accounting and status

New live calls are accounted only through existing normal-spine records:

- projected usage and cost use 059b reservations;
- completed usage and cost use `ai_jobs` and `egress_attempts`;
- active and in-flight reservations count before admission;
- stale in-flight work uses existing conservative reconciliation;
- completed usage is reconciled exactly once;
- no new call increments the legacy direct-smoke counters.

Legacy counters remain historical compatibility fields. Gate and status totals use finalized normal-spine Scaleway usage plus budget-relevant reservations and may include legacy historical usage only as a disjoint pre-094 component. No completed call may be counted twice.

`/ai/status` is informational and must agree with the next normal-spine admission decision for credential state, cap exhaustion and `external_calls_allowed`.

## Binding decision 5 — failure and fallback

`external:scaleway` has no fallback chain.

HTTP success with missing choices, empty content or malformed provider payload is a provider error, not a successful AI task. The normal reservation and attempt evidence remains authoritative and no alternate provider is attempted.

Credential, policy, budget, sensitivity, packet, ticket or binding failure blocks before transport whenever the relevant authority can be evaluated pre-dispatch.

## Implementation ownership

One fresh implementation branch derived from the exact merged definition/readiness head owns delivery. The closed `fix/082-scaleway-spine-checkpoint` branch and PR #219 must not be reopened, merged, rebased into the implementation or treated as authority. They may be consulted only as adverse review evidence.

Expected bounded paths are:

- `configs/ai_providers.yaml` for the dedicated provider/model/route and explicit no-fallback contract;
- provider registry and adapter construction only for provider-specific selection and isolated route-model override validation;
- the existing Scaleway adapter/provider only for the concrete registry-selected model, endpoint compatibility and malformed/empty response handling;
- shared execution/budget/status modules only where needed to expose the already authoritative normal-spine usage and reservation state;
- existing live smoke and smoke-console services/routes only to become wrappers over `run_ai_task`;
- focused 094 tests and unchanged registry, 059b, token-flow and smoke regressions;
- `docs/specs/STATUS.md` only for normal implementation lifecycle transitions.

No frontend, credential persistence, recovery, sensitivity policy, promotion, fallback-chain redesign, database migration, new table or second ledger is expected. If the current schema or execution service cannot represent the wrapper-originated call without a new state store or authority bypass, stop and return 094 to `planned`.

## Required delivery gates

The implementation PR may merge only when deterministic tests prove:

- `external:scaleway` resolves uniquely and existing route identities and fallback chains are unchanged;
- the provider-specific Scaleway adapter is retained while generic providers remain generic;
- the exact registry model and fallback index zero are packet-, decision-, reservation-, attempt- and job-bound;
- legacy `SCALEWAY_MODEL` cannot alter or break global route resolution;
- any route-specific override is distinct, registered and fail-closed;
- every live smoke and console call enters through the shared execution service and cannot invoke transport directly;
- first-use confirmation and restart-safe ticket resume remain owned by 059b;
- concurrent route and wrapper calls cannot reserve beyond global or provider caps;
- active/in-flight reservations and finalized usage are counted without double counting;
- status and execution gate decisions agree for route-only, historical-only and mixed usage;
- counter reset or settings mutation cannot erase an identifiable normal-spine reservation;
- empty or malformed provider content produces provider error and no fallback;
- missing, corrupted or unusable credential blocks without secret exposure;
- exact-key and unique-substring test sentinels do not appear in responses, logs, events, SQLite or repository files;
- full backend pytest, Ruff, spec-status gate and BLUECAD canary are terminal green;
- CI makes no live provider call and needs no real key or Windows account.
