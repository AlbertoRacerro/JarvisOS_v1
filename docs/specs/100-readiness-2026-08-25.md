## 1. Exact runtime and authority findings

Fresh inspection of the exact authority base confirms:

- `frontend/src/theme.ts` is the existing visual-preference owner for safe local `system | light | dark` appearance and is the only authorized owner to extend with local-only accent preference;
- `frontend/src/styles/tokens.css` already centralizes typography, radii, motion, elevation and light/dark semantic color channels;
- `frontend/src/App.tsx` plus `frontend/src/components/Layout.tsx` own the one application shell, one Jarvis/Properties sidecar and one Analysis Dock composition;
- `frontend/src/pages/Settings.tsx` is the existing appearance/settings surface;
- `frontend/src/pages/BlueCAD.tsx` is the hard Model/viewport proof surface;
- `frontend/src/pages/EngineeringData.tsx` is selected as Proof C because it is the harder dense state on the authority base: it combines more lifecycle/status/action semantics than the Runs surface and therefore better exposes accent/status regressions;
- `frontend/src/stages/ProcessStage.tsx` is the merged 058d inert Process scaffold and remains presentation-only;
- `frontend/src/components/ai/JarvisSidecar.css` and the existing `useJarvisSidecar.tsx` behavior belong to the single Jarvis surface; visual work must not create another AI state or action owner;
- `frontend/src/components/analytics/AnalyticsDockContent.tsx` remains persisted-run evidence, not process-topology authority;
- `frontend/package.json` currently contains no generic icon library and no visual/theme/color/picker/animation dependency;
- no Playwright or other browser-test framework is present in the repository. 100 therefore does not add a browser framework merely for evidence; real-browser evidence remains an external/evidence harness concern while deterministic acceptance stays dependency-light in `frontend/tests/`.

The binding aesthetic/product authority is the exact-master Visual Identity Authority Pack plus `docs/specs/100-visual-identity-1.md`. The current provisional UI is not aesthetic authority.

## 3. Accent implementation freeze

The single visual preference owner in `theme.ts` extends appearance with an independently stored accent preference. It does not alter `system | light | dark` semantics.

Freeze exactly these user-facing choices:

1. Microalgae — `#528B68` — default;
2. Leaf Chlorophyll — `#5F8F52`;
3. Lagoon — `#4F938A`;
4. Custom.

Custom uses the native `<input type="color">` plus a validated editable six-digit HEX field and Reset. No picker dependency is authorized.

Acceptance rules:

- malformed or stale stored accent data fails to Microalgae before application;
- malformed Custom HEX never reaches CSS/application state;
- Reset restores Microalgae;
- accent persistence is local visual preference only and creates no API/backend/canonical write;
- derived tonal channels use CSS variables and native `oklch()` / `color-mix(in oklch, ...)` where supported by the current browser, with deterministic non-mixed seed/fallback values declared so unsupported computation cannot make the UI unreadable;
- no color-library dependency is authorized;
- accent variables are physically separate in tokens from error/warning/success/proposed/stale/unavailable and scientific/categorical color channels.

Mandatory adversarial Custom proof seed: warm orange `#C46B2B`.  
Second materially different Custom proof seed: cool violet-blue `#5B6FD8`.

Changing between any preset/Custom seed must leave semantic/scientific token values invariant.

## 4. Typography, geometry, material and motion freeze

Implementation starts from the full-spec scale and authority pack:

- metadata 12px;
- labels 13px;
- body/table 14px;
- section title 16px;
- page/workbench title 21–24px;
- no required operating information below 12px;
- `font-variant-numeric: tabular-nums` for repeated engineering values/aligned numeric columns;
- structural controls roughly 30px compact and 34–36px normal;
- structural panel/control radii 6–8px;
- floating/transient/Jarvis surfaces may reach 10–12px only where they remain secondary to the engineering structure;
- no universal pills/large-radius card language;
- mineral light seed surfaces and text/border values from the full spec are the canonical starting point;
- dark is parity, using charcoal/mineral darks rather than pure-black/neon identity;
- ordinary transitions remain in the 80–180ms bounded token system and never gate action completion;
- `prefers-reduced-motion` collapses non-essential motion effectively to immediate behavior;
- any indefinite animation must be coupled to an actual pending state and terminate when that state terminates; no fake percentage/progress.

Token seed values may change only to correct a concrete browser/contrast/readability failure recorded against an exact head.
