## 1. Exact runtime findings

Fresh inspection of the merged definition base establishes the following current seams:

- `frontend/src/app/routes.ts` owns `StageKind`, `RouteId`, `PRODUCTION_ROUTES`, `DESIGN_STAGE_ITEMS`, pathname normalization and canonical replacement decisions.
- `frontend/src/app/useAppRouter.ts` already implements canonical replace semantics: `resolveRoute()` returns `canonicalPath` + `shouldReplace`, initial/popstate synchronization uses `history.replaceState`, and internal navigation resolves a route before push/replace.
- `frontend/src/stages/registry.ts` is the sole primary stage registry. The current `flowsheet` entry renders `FlowsheetStage`.
- `frontend/src/stages/FlowsheetStage.tsx` is semantically lineage, not process topology: it calls lineage graph/node/freshness APIs, carries workspace/request-generation stale guards, publishes lineage selection, and renders `Lineage / Dependency & provenance` with explicit read-only/no-recomputation wording.
- `frontend/src/App.tsx` is the single owner of workspace, stage selection, shell contributions, Jarvis composition and the 071b Properties controller. A route-id change clears selection, shell contributions and shell-region requests.
- `frontend/src/components/shell/ContextualNavigator.tsx` derives Design stage links exclusively from `DESIGN_STAGE_ITEMS`.
- `frontend/src/components/Layout.tsx` owns the one Navigator, one Jarvis/Properties sidecar and one Analysis Dock. The dock control exists globally; route/stage composition only supplies content.
- `frontend/src/components/analytics/AnalyticsDockContent.tsx` is existing 089 real-data analytics over persisted runs/model contracts. It is workspace-scoped and stale-safe, but it is not process-topology analytics.

No backend process-topology or process-object authority exists that 058d may legitimately expose.

## 2. Minimum route/type migration

Implementation must use the existing router; no second routing layer is authorized.

Freeze these target semantics:

- add `StageKind = ... | "process" | "lineage"` and remove the ambiguous normal-stage `flowsheet` kind;
- replace route id `design-flowsheet` with canonical route ids `design-process` and `design-lineage`;
- canonical `/design/process` -> Process stage;
- canonical `/design/lineage` -> Lineage stage;
- historical `/design/flowsheet` is handled inside `resolveRoute()` as a compatibility alias that returns the canonical Lineage route with `canonicalPath="/design/lineage"` and `shouldReplace=true`;
- `/design/flowsheet/` and the existing query/hash normalization behavior must continue to canonicalize through the same resolver rather than a component redirect;
- no third visible Flowsheet stage remains.

Because `useAppRouter.synchronize()` already performs `history.replaceState` whenever `shouldReplace` is true, the alias requires no new router state or redirect component. Internal navigation to the historical alias must also resolve directly to the canonical Lineage target before adding history.

## 4. Lineage component migration

Minimum safe implementation: rename `frontend/src/stages/FlowsheetStage.tsx` to `frontend/src/stages/LineageStage.tsx` and rename the component/export plus local accessibility ids from `flowsheet-stage-*` to lineage naming.

Reason: retaining a file/component called Flowsheet after the UI vocabulary has split Process from Lineage would preserve the semantic collision in code and make later maintenance failure-prone. The file is self-contained and already lineage-specific, so the rename is bounded and type-safe.

The body of lineage runtime behavior is otherwise frozen:

- same lineage APIs;
- same workspace discovery;
- same generation/request stale guards;
- same selection semantics;
- same diagnostics/freshness behavior;
- same read-only/no-recomputation claim.

No lineage backend/API change is authorized.

## 5. Process stage shape

Add one bounded `frontend/src/stages/ProcessStage.tsx`.

It is presentation-only and owns no engineering/process truth. It may contain only:

- a compact inert toolbar region;
- an inert/empty process-equipment palette region;
- a dominant central canvas placeholder;
- truthful empty-state/status copy.

Required truth claim: process topology editing is unavailable until server-owned process/evaluator contracts are integrated.

Permitted controls are disabled/static only. No draggable items, fake streams, fake equipment instances, coordinates, connectivity, engineering values, validation state or solver buttons.

Process stage local React state, if any, may only control ephemeral presentation such as whether an inert palette help section is open. No localStorage/sessionStorage or durable topology/layout state.

## 7. Shell-region composition

Reuse the existing shell owners unchanged:

- Navigator: existing `ContextualNavigator` + `DESIGN_STAGE_ITEMS` is sufficient for stage switching. Process does not need a second global navigator. Any palette is a stage-local inert region inside the process scaffold.

- Analysis Dock: reuse existing 089 `AnalyticsDockContent` as real persisted-run evidence by extending the existing App-level dock-content condition to include `route.id === "design-process"`. No process KPI, process run type or process observation may be fabricated.
