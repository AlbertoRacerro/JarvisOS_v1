## Frozen Requirement closure

127 implementation MUST retain the public compatibility PATCH and make it behaviorally owner-equivalent rather than delete it merely because no current central frontend consumer was confirmed.

The retained request contract is `RequirementProjectUpdate` or an equally narrow successor with:

- required `workspace_id`;
- required `expected_updated_at`;
- ordinary canonical edit fields only;
- generic `status` mutation removed/forbidden because Requirement retirement has a dedicated owner transition;
- `basis_kind`, `reconciliation_gate` and criterion metadata editable only under the Project Knowledge owner/CAS/audit transaction;
- no automatic stale retry.

`backend/app/modules/modeling/project_knowledge_owner.py::update_requirement_in_transaction` is the canonical edit seam. Before `_cas_update` writes anything, it must combine the current row plus requested fields and validate that complete candidate through the existing canonical Requirement schema/invariant. Response serialization must never be the first detector of an invalid merged row.

The current accepted Requirement invariant is preserved exactly; 127 must not silently strengthen it. In particular, readiness does not redefine whether an `acceptance_criterion` with all criterion metadata absent is valid. It only requires that any current canonical cross-field invariant be checked on the merged candidate before persistence.

Failure is atomic: semantic rejection, stale token or wrong-workspace rejection leaves row contents, `updated_at` and audit/event history unchanged.

## Error contract

Minimum affected public behavior:

- `ProjectKnowledgeOwnerError("owner_stale", ...)` -> HTTP 409 with stable machine-readable code;
- `owner_not_found` for the supplied workspace -> stable not-found/isolation response without revealing cross-workspace existence;
- forbidden generic lifecycle authority -> stable 400/422 coded response;
- invalid post-merge Requirement state -> stable 400/422 coded response;
- persistence failures remain bounded and must not collapse owner/domain failures into generic 500.

This is a local adapter in `modeling/routes.py`, not a repository-wide error-taxonomy refactor.
