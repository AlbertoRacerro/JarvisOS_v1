# 103 PROCESS-UPSTREAM-BAKEOFF-1 — targeted qualification evidence

Scope: REF-038, REF-039, REF-040, REF-042, REF-047 from `docs/IDEA_INTAKE_AND_CANDIDATE_INTEGRATIONS.md`. This is an offline WSL2 feasibility probe of isolated candidate environments plus a native Windows 11 import/single-call smoke, not a validated BlueRev process model. The synthetic point is 298.15 K and 101325 Pa; the dynamic biomass variable and coefficients are arbitrary fixture values. No product dependency or solver adapter is added by 103.

## Reproduction and evidence

Candidates run in two isolated venvs, never the backend venv: `base` (Python 3.11; pins in `scripts/qualification/103/freeze-base.txt`) and `bio` (Python 3.12; pins in `scripts/qualification/103/freeze-bio.txt`) because the BioSTEAM stack needs a different NumPy/Numba pair. From the repository root run `<base>/bin/python scripts/qualification/103/probe.py --only CoolProp chemicals thermo fluids ht pyomo idaes-pse watertap scikit-sundae casadi do-mpc fmpy openmdao neqsim`, then `NUMBA_DISABLE_JIT=1 <bio>/bin/python scripts/qualification/103/probe.py --venv-role bio --only thermosteam biosteam qsdsan`. Local tools are supplied by environment: `Q103_FMU` (Reference-FMUs v0.0.39 `2.0/Dahlquist.fmu`), `Q103_SOLVER_LIB` (Fortran runtime directory for the IDAES IPOPT binary on `~/.idaes/bin`) and `Q103_JAVA_HOME` (Java 17 for NeqSim). The script writes one JSON per candidate, including interpreter, environment, version, metadata license, elapsed wall time, and measurements or native error. BioSTEAM's JIT-enabled import failed with Numba `cannot cache function 'normalize': no locator available`; the reported BioSTEAM/ThermoSTEAM/QSDsan measurements are therefore interpreter-mode feasibility only, with JIT disabled, and not representative performance. `backend/tests/test_process_upstream_103_results.py` checks artifact completeness without optional imports.

## Adapter and authority boundary

Any 104+ adapter implements frozen `backend/app/modules/engineering/evaluator_contracts.py` `EngineeringEvaluator`: `descriptor`, truthful `availability`, and typed `evaluate`. It consumes frozen 145 project/subject/quantity refs and 102 `FidelityTier`/`ScientificQualificationRecord`; backend-native case bundles live in `backend_case_ref`, with bounded `backend_options`. The result records native failure code and shared category, numerical diagnostics, artifacts, validity and evidence references. `available` means runnable here; `converged` means solver health; neither means qualified or validated. This 103 probe does not itself emit product `EvaluationResult` or create a 102 qualification record.

047 is **screening** fidelity. The static property/pipe/recycle probes do not establish `steady_state_detailed` until balances, physical assumptions and a reference dataset are checked. The day/night fixture does not establish `dynamic_detailed` scientific qualification. The controller/study layer may request evaluations but must not silently promote fidelity or validity. Product AI, if later used for interpretation, still runs only through `run_ai_task` with an `ai_jobs` row; solvers never receive policy, provider, promotion or canonical-store authority.

For each dynamic simulation one orchestrator owns advancing time and accepting state. CVODE, IDA, an FMU master, or a selected process simulator can take that role for a run. CasADi may supply expressions/Jacobians and do-mpc may propose controls at synchronization points, but they cannot concurrently advance the authoritative state. A co-simulation must name its master, event/step contract, restart snapshot, and balance reconciliation before being treated as a plant run.

## Platform, license and missing evidence

The probe results above ran on WSL2 Ubuntu (Linux 6.18 WSL2 kernel) in the two isolated venvs. A native Windows 11 smoke (`scripts/qualification/103/windows/`, Windows 11 10.0.26200, CPython 3.12.10, fresh venv under `%LOCALAPPDATA%`) installed candidates from PyPI and ran one call each: CoolProp water density 997.047636760347 kg/m3 (identical to WSL2), `fluids` Darcy f 0.0203718640184167 (identical), `ht` Dittus-Boelter Nu 300.12670249791796 at Re 56011.23596 (identical to WSL2 `ht` 1.2.0 for the same input; the WSL2 probe row above used Re 56011.0, hence 300.12569), `thermo` water density 997.04830, CasADi symbolic expression, scikit-sundae CVODE exp(-1) test 0.36792, OpenMDAO `Problem`, and FMPy/do-mpc/IDAES imports. Two Windows limits are real: `pip install biosteam` failed building the `numpoly` wheel (no prebuilt wheel for that interpreter, no compiler), and Pyomo found no IPOPT (`idaes get-extensions` was not run). The Windows smoke is import/single-call evidence only; the recycle, DAE, MPC, FMU and NeqSim cases were not repeated there, and chemicals/QSDsan/WaterTAP/NeqSim were not installed on Windows. Optional candidates stay out of `backend/requirements.txt` until an adapter slice selects them.

License strings in the JSON are distribution metadata, not a legal determination. The measured stack includes MIT, BSD variants, Apache-2.0, NCSA (QSDsan 1.5.3), and LGPLv3+ (CasADi/do-mpc); IPOPT reports EPL. FMPy metadata does not declare a license in the fields probed; inspect upstream license files before packaging. DWSIM/CAPE-OPEN have GPL/proprietary or platform integration boundaries that require separate legal and Windows review; no assumption of redistribution rights is made.
