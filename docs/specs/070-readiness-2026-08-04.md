# Spec 070 readiness decision — 2026-08-04

## Decision

Spec 070 — UI-FOUNDATION-1 is promoted from `planned` to `ready`.

This decision authorizes one bounded implementation of the merged contract in
`docs/specs/070-ui-foundation-1.md`. It does not authorize spec 083 application
shell work, router or deep-link authority, a settings page, a UI framework, a
state library, a CSS processor, a frontend test framework, backend changes,
schema or migration work, provider calls, new spend, or Three.js scene-internal
theming.

## Implementation ownership

One branch, `spec/070-ui-foundation-1`, and one implementation PR own delivery.
Parallel UI-foundation or shell implementation PRs are not authorized.

The assigned implementation and merge owner is the current JarvisOS repository
agent operating under `AGENTS.md`. Merge requires exact-head deterministic gates
and no unresolved blocking finding.

`docs/specs/STATUS.md` may change only for the normal 070 lifecycle transitions:

1. `ready` → `in_progress` when the implementation branch/session starts;
2. `in_progress` → `in_review` with the implementation PR number when the PR opens;
3. `in_review` → `merged` after exact-head merge and registry reconciliation.

No other registry row may change in the implementation.

## Required implementation gates

The implementation PR may merge only when all of the following are terminal
green on the exact head:

```text
python scripts/check_ui_foundation.py
cd frontend
npm ci
npm run build
```

plus repository-standard spec-status, backend Pytest, Ruff, BLUECAD geometry
canary, and strict real-tool proof gates.

The implementation PR must also record a bounded Windows-capable browser matrix
covering:

- initial load in `system`, `light`, and `dark`;
- invalid and unavailable storage;
- live OS-theme changes while `system` is selected;
- keyboard operation and visible focus;
- 200% browser zoom;
- one compact desktop width;
- Dashboard, System Status, Domain Foundation, AI Draft, BLUECAD, and
  development-only chat reachability;
- one real BLUECAD candidate and GLB artifact when available;
- one error, warning, loading, empty, or unavailable state;
- computed WCAG AA contrast evidence for core text, accent, focus, warning,
  danger, and success pairs in both themes.

This evidence must contain no secrets, provider responses, sensitive project
content, or credential-derived values. No screenshot is required for 070 alone.

## Binding exclusions

The implementation must not add or imitate:

- the 083 router, deep links, rail, top bar, PrimaryStage registry, contextual
  sidecar, navigator, analysis dock, or legacy diagnostic routes;
- 084–092 frontend surfaces;
- a settings page or secret-management UI;
- new backend statuses, evidence meanings, cost calculations, or provider
  authority;
- a global state framework, component platform, design-system site, icon
  package, modal framework, data grid, toast system, or visual-test platform;
- mobile-first or 320-pixel product redesign;
- Three.js scene palette changes.

`local_compute`, no-execution, synthetic/fake, and external-provider evidence
remain distinct. Only a real local invocation without a cost model may be
labelled `unpriced`.

## Rollback boundary

If the acceptance criteria require a router, global state framework, UI
framework, CSS processor, frontend test framework, backend contract change,
renderer-internal change, non-enum browser persistence, or loss of current
BLUECAD/AI/scenario/system/domain/diagnostic behavior:

1. stop the implementation;
2. retain the failing evidence;
3. leave current frontend runtime behavior intact;
4. return 070 to `planned` or `blocked` with the exact reason;
5. do not absorb the conflict into 083 or widen 070 silently.

## Readiness conclusion

The exact baseline satisfies all section-16 readiness requirements of the merged
070 definition. The next authorized front is the single bounded
`spec/070-ui-foundation-1` implementation.
