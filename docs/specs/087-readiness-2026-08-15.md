# 087 LINEAGE-OVERVIEW-1 — readiness decision — 2026-08-15

Readiness baseline: `e9fa83492709e634b7cfa72531f633b926a3c418` (merge of definition PR #248).

## Decision

087 is implementable as one bounded frontend-only slice over the already-merged 050/051 backend authority. Runtime implementation remains unauthorized until this readiness record and the corresponding `docs/specs/STATUS.md` promotion to `ready` are merged.

The minimum-necessary representation is a deterministic accessible list/adjacency workbench. No graph-layout dependency, force-directed canvas, saved coordinates, minimap, zoom engine, clustering, backend amendment, schema change, new state store, or global visual-identity work is justified.

## Exact authority frozen from runtime

The implementation must derive its TypeScript models from `backend/app/modules/flowsheet/models.py` on the readiness baseline, not from illustrative prose. In particular:

- `FlowsheetNodeRead.kind` is the exact backend `NodeKind` union: `model_spec`, `model_version`, `simulation_run`, `runner_job`, `artifact`, `assumption`, `parameter`, `decision`, `requirement`, `ai_job`, `bluecad_candidate`, `bluecad_attempt`, `evidence`;
- node metadata values are `str | int | float | bool | None`;
- `FlowsheetGraphRead.topological_order` is nullable;
- edge class is exactly `dependency | provenance`;
- diagnostics expose unsupported/malformed/dangling/cycle/manual-binding counts plus bounded unresolved references and cycle paths;
- freshness state is exactly `fresh | stale`;
- latest invalidation fields such as `affected_count`, `graph_digest`, `reason_code`, `path`, and `path_digest` are nullable where the backend model says so.

The only normal read APIs authorized are the existing 050/051 routes:

- `GET /workspaces/{workspace_id}/flowsheet/graph`;
- `GET /workspaces/{workspace_id}/flowsheet/nodes/{node_ref}`;
- `GET /workspaces/{workspace_id}/flowsheet/nodes/{node_ref}/freshness`.

The frontend must not join unrelated endpoints, inspect arbitrary record payloads, or infer freshness consequences from provenance edges.

## Selection mapping

The existing `RecordResource` taxonomy on this baseline is limited to `workspace`, `model-spec`, `assumption`, `parameter`, `simulation-run`, `decision`, and `bluecad-candidate`.

087 may publish shell `StageSelection` only for exact canonical node kinds with an existing semantic resource mapping:

- `model_spec` → `model-spec`;
- `assumption` → `assumption`;
- `parameter` → `parameter`;
- `simulation_run` → `simulation-run`;
- `decision` → `decision`;
- `bluecad_candidate` → `bluecad-candidate`.

All other supported 050 node kinds remain locally selectable and fully inspectable through the flowsheet read APIs, but must not expand or fake the global selection taxonomy in 087.

## Presentation and state decisions

- Use the backend deterministic node order. When `topological_order` is non-null and the graph is acyclic it drives dependency sequence; remaining nodes stay in response order. Cyclic graphs remain inspectable without synthetic reordering.
- Use explicit upstream → downstream text semantics. Dependency/provenance distinction is textual/accessibility-visible, never colour-only.
- Navigator controls are limited to visible-label/ref search and an exact kind filter. Edge-class filtering is omitted unless implementation proves both classes unreadable without it.
- If filtering hides the selected node, keep the local selection and inspector state; show a small `hidden by current filter` explanation. This avoids selection churn and preserves operator context. Focus remains on the filter control that caused the change rather than being moved programmatically.
- Sidecar is sufficient for selected-node detail, freshness, latest invalidation path and compact direct relationship summary.
- Do not add a dock contribution by default. Graph diagnostics belong in the stage header/body as a compact disclosure because they describe the whole graph. A new dock contribution would add persistent layout complexity without a required acceptance benefit.
- No automatic polling.

## Request-race contract

Graph, node-detail and freshness reads require monotonically increasing request generations plus exact workspace/node identity checks. A response is accepted only if both generation and current identity match the initiating request. This must reject A → B → A and X → Y → X stale completions, not merely A → B or X → Y.

Workspace change synchronously clears prior graph, local selection, detail and freshness before new loading begins. Node selection synchronously clears old detail/freshness before new reads begin.

A detail/freshness 404 after graph load is presented as read drift: retain graph context, mark the selected node unresolved, offer graph refresh, and do not remap identity.

## Exact implementation allow-list

Runtime implementation is limited to:

- `frontend/src/api/client.ts`;
- `frontend/src/stages/FlowsheetStage.tsx`;
- `frontend/src/components/lineage/**` only when a small helper/component materially improves readability or deterministic testing;
- existing local frontend stylesheet(s) already used by the shell/stages;
- `scripts/check_lineage_overview.py`;
- one focused dependency-free/TypeScript state harness for ordering, mapping and stale-response acceptance if static checker coverage cannot prove those semantics;
- `docs/specs/STATUS.md` for lifecycle state only.

`frontend/src/app/selection.ts` is explicitly outside the allow-list: 087 must not broaden global selection taxonomy.

Backend files, schemas, migrations, package manifests, lockfiles, workflows, providers, credentials and global visual-identity tokens are forbidden unless the current authority proves a required acceptance criterion impossible; in that case stop and document the insufficiency rather than silently expanding scope.

## Deterministic checker and proof

The 087 checker must fail on at least:

- placeholder-only Flowsheet stage;
- missing typed graph/node/freshness client functions;
- broad `unknown`/arbitrary-payload rendering used to bypass stable 050/051 fields;
- mutation/recompute/rerun/stale-clear controls inside the 087 surface;
- invented confidence/health/severity/impact/recompute estimates;
- dependency/provenance distinction that is colour-only;
- enlargement of `RecordResource` solely for 087;
- lifecycle registry drift.

A focused state harness must cover A → B → A and X → Y → X acceptance, unsupported-to-global-selection kinds, deterministic ordering with nullable topological order/cycles, and selected-node-hidden-by-filter behavior if those contracts are not directly testable in existing tests.

## Exact-head acceptance gates

One unchanged implementation SHA must pass:

1. repository CI and existing frontend preservation checkers required by the current queue;
2. `python scripts/check_lineage_overview.py --self-test` and normal checker execution;
3. the focused 087 state harness if added;
4. `npm ci` and `npm run build` from `frontend/`;
5. browser proof using real or deterministic fixture-backed 050/051 responses for: graph loading/success/empty/failure, cycle + diagnostics, node selection, dependency/provenance semantics, stale vs historical status separation, freshness unavailable, disappeared-node 404 drift, keyboard navigation/focus, long refs and effective-200%-zoom with no page-level horizontal overflow;
6. preservation smoke for Model, BLUECAD, Results and Review routes/shell behavior;
7. exact-head semantic self-review with no material P0/P1/P2 finding.

External reviewer availability is advisory and cannot substitute these gates.

## Rollback

Rollback is deletion/reversion of the 087 frontend surface, typed client additions, checker/harness and registry lifecycle change, restoring the prior Flowsheet placeholder. No migration, persisted UI state or backend cleanup exists.

## Minimum-necessary test

- New graph library? **No.** Existing deterministic 050 ordering plus native semantic markup is sufficient.
- Backend read-model change? **No.** Exact merged models already expose graph, bounded node detail, diagnostics and freshness explanation required by the accepted definition.
- Global selection expansion? **No.** Six existing resource mappings cover semantic shell handoff where valid; all other graph kinds can remain stage-local.
- New dock? **No by default.** Whole-graph diagnostics fit the stage surface; selected detail belongs in sidecar.
- New shared state abstraction? **No.** One FlowsheetStage-owned state with small pure helpers is sufficient.
