## Exact authority frozen from runtime

The implementation must derive its TypeScript models from `backend/app/modules/flowsheet/models.py` on the readiness baseline, not from illustrative prose. In particular:

- `FlowsheetNodeRead.kind` is the exact backend `NodeKind` union: `model_spec`, `model_version`, `simulation_run`, `runner_job`, `artifact`, `assumption`, `parameter`, `decision`, `requirement`, `ai_job`, `bluecad_candidate`, `bluecad_attempt`, `evidence`;
- node metadata values are `str | int | float | bool | None`;
- `FlowsheetGraphRead.topological_order` is nullable;
- edge class is exactly `dependency | provenance`;
- diagnostics expose unsupported/malformed/dangling/cycle/manual-binding counts plus bounded unresolved references and cycle paths;
- freshness state is exactly `fresh | stale`;
- latest invalidation fields such as `affected_count`, `graph_digest`, `reason_code`, `path`, and `path_digest` are nullable where the backend model says so.

The only normal lineage read APIs authorized are the existing 050/051 routes:

- `GET /workspaces/{workspace_id}/flowsheet/graph`;
- `GET /workspaces/{workspace_id}/flowsheet/nodes/{node_ref}`;
- `GET /workspaces/{workspace_id}/flowsheet/nodes/{node_ref}/freshness`.

The frontend must not join unrelated engineering endpoints, inspect arbitrary record payloads, or infer freshness consequences from provenance edges.

## Selection mapping

087 may publish shell `StageSelection` only for exact canonical node kinds with an existing semantic resource mapping:

- `model_spec` → `model-spec`;

- `simulation_run` → `simulation-run`;

All other supported 050 node kinds remain locally selectable and fully inspectable through the flowsheet read APIs, but must not expand or fake the global selection taxonomy in 087.

## Presentation and state decisions

- Use the backend deterministic node order. When `topological_order` is non-null and the graph is acyclic it drives dependency sequence; remaining nodes stay in response order. Cyclic graphs remain inspectable without synthetic reordering.
- Use explicit upstream → downstream text semantics. Dependency/provenance distinction is textual/accessibility-visible, never colour-only.
- Navigator controls are limited to visible-label/ref search and an exact kind filter. Edge-class filtering is omitted unless implementation proves both classes unreadable without it.
- If filtering hides the selected node, keep the local selection and inspector state; show a small `hidden by current filter` explanation. This avoids selection churn and preserves operator context. Focus remains on the filter control that caused the change rather than being moved programmatically.
- Sidecar is sufficient for selected-node detail, freshness, latest invalidation path and compact direct relationship summary.
- Do not add a dock contribution by default. Graph diagnostics belong in the stage header/body as a compact disclosure because they describe the whole graph. A new dock contribution would add persistent layout complexity without a required acceptance benefit.
- No automatic polling.

## Request-race contract

Graph, node-detail and freshness reads require monotonically increasing request generations plus exact workspace/node identity checks. A response is accepted only if both generation and current identity match the initiating request. This must reject A → B → A and X → Y → X stale completions, not merely A → B or X → Y.

Workspace change synchronously clears prior graph, local selection, detail and freshness before new loading begins. Node selection synchronously clears old detail/freshness before new reads begin.

A detail/freshness 404 after graph load is presented as read drift: retain graph context, mark the selected node unresolved, offer graph refresh, and do not remap identity.

## Runtime sufficiency amendment — workspace binding — 2026-08-15

Implementation PR #250 exposed a concrete prerequisite mismatch that the original readiness audit missed: on exact merged runtime `12fb2beab254adfd3dfcf31c04dc798ab266898e`, `App.tsx` passes `workspaceId={null}` to every primary stage and owns no workspace state. Therefore an 087 implementation that obeys the original allow-list can render only its `Select a workspace` empty state and can never issue an authorized workspace-scoped 050/051 read. This is a runtime blocker, not a browser-proof or styling issue.

The minimum sufficient correction is to complete the already-declared 083 `PrimaryStageProps.workspaceId` seam rather than move workspace authority into 087 or duplicate engineering state:

- `frontend/src/App.tsx` may own one transient `workspaceId: string | null` and pass it to primary stages;
- `frontend/src/stages/registry.ts` may add one typed `onWorkspaceChange(next: string | null): void` callback to `PrimaryStageProps`;
- `FlowsheetStage` may use the already-existing shared `listWorkspaces()` client solely for workspace discovery and present one bounded workspace selector that requests changes through `onWorkspaceChange`;
- the first successful workspace-discovery response may select its first returned workspace only when the shell has no current workspace; explicit later operator selection remains authoritative;
- workspace discovery must be stale-response guarded and failure/empty states must remain distinct;
- changing workspace must synchronously clear graph-derived selection/detail/freshness before the new graph read, as already frozen;
- no workspace value is persisted, inferred from lineage, copied into a second store, placed in URL/query/hash, or treated as engineering truth;
- Model/BLUECAD may continue using its existing internal workspace lifecycle in this slice. 087 must not refactor 085 merely to consume the new shell workspace seam.

This amendment authorizes exactly these additional implementation paths for #250:

- `frontend/src/App.tsx`;
- `frontend/src/stages/registry.ts`.

It also authorizes the already-existing `GET /workspaces` through the shared `listWorkspaces()` function as workspace discovery only. The three 050/051 endpoints remain the sole lineage-data authority. No backend, schema, package, lockfile, workflow, global visual identity, URL workspace state, or new shared-state framework is authorized.

### Amendment acceptance evidence

Before #250 may merge, one exact implementation head must additionally prove:

1. direct `/design/flowsheet` load with at least one workspace reaches a real lineage graph rather than remaining permanently in `Select a workspace`;
2. two-workspace selection changes drive the shell-owned `workspaceId`, clear prior graph-derived state immediately, and reject late workspace-discovery/graph completions;
3. zero-workspace and workspace-discovery failure states are distinct and usable;
4. Model, Results, Review and BLUECAD preservation remains unchanged;
5. the 087 checker rejects regression to a permanently-null primary-stage workspace binding.

- Local workspace owner inside `FlowsheetStage`? **Rejected.** It would contradict the accepted shell-owner contract and create a second workspace authority.
- Persisted/global workspace service or new context framework? **Rejected.** One transient App state plus the existing typed stage seam is sufficient.
- Top-bar/global workspace redesign? **Rejected.** 087 needs only a bounded lineage workspace selector; global navigation/identity redesign remains outside scope.
- Refactor BLUECAD to the new seam now? **Rejected.** 085 is already merged and working; forcing convergence is unrelated to making 087 usable.

This amendment supersedes only the original 087 readiness statements that `App.tsx`/`registry.ts` are outside scope and that no workspace-discovery read is needed. All other boundaries and gates remain unchanged.
