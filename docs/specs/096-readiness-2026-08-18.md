## 1. Exact current owners

Fresh master inspection establishes these owners:

- `frontend/src/App.tsx` composes route content, the App-owned 091 Jarvis sidecar contribution and the 089 Analytics Dock contribution. It must remain the owner of Jarvis request/thread state; 096 may compose presentation but must not create a second execution controller.
- `frontend/src/components/Layout.tsx` owns shell panel open/close state, focus return, route-close behavior and placement of `ContextualSidecar` / `AnalysisDock`.
- `frontend/src/components/shell/ContextualSidecar.tsx` owns the single right-sidecar shell, heading focus and Escape close behavior. It currently renders one `content` contribution or a truthful fallback from `StageSelection`.
- `frontend/src/components/ai/useJarvisSidecar.tsx` + `JarvisSidecar.css` own 091 transcript/composer/thread/context interaction and stale/in-flight request behavior. These semantics must survive split/tab presentation unchanged.
- `frontend/src/pages/RunsWorkbench.tsx` owns Runs list/detail, input/binding/result payload projection, logs and artifact detail. Its current raw/log `<pre>` regions are the direct page-height expansion risk.
- `frontend/src/components/analytics/AnalyticsDockContent.tsx` and `frontend/src/components/shell/AnalysisDock.tsx` own 089 analysis composition. App mounts it for Runs and Engineering Data; 096 must not move calculation/comparability authority into Runs.
- 054 Review remains stage-owned through the existing stage/registry contribution and review state helpers under `frontend/src/components/review/`; 096 may change only its presentation hierarchy.

## 2. Sidecar split feasibility

The 40–45% Jarvis / 55–60% Properties desktop split can be achieved without a shell architecture rewrite. The minimum seam is the existing single `ContextualSidecar`: keep its outer aside/header/Escape/focus authority, render one bounded internal workbench composition, and keep the existing App-owned Jarvis React node mounted as the upper region.

A small `ContextualSidecar` presentation change plus local CSS is authorized because the current component accepts only one opaque `content` node and otherwise cannot expose two independently scrollable regions. `Layout.tsx` should remain unchanged unless browser evidence proves a height constraint cannot be expressed from the existing sidecar shell; if touched, only sizing/composition is allowed, never ownership or route behavior.

At compact/effective-200% geometry, the same mounted Jarvis/Properties content may be presented as a keyboard-operable tabset. Switching tabs must be CSS/local UI visibility, not a second sidecar or a new Jarvis controller.

## 3. Truthful Properties content available now

Before 071b/092, Properties is deliberately limited. Current authority can truthfully show:

- `StageSelection.kind` and, for record selections, existing `resource`, `workspaceId`, `recordId` under a compact selection summary / Technical details;
- for geometry-hit selections, only the fact that the hit is ephemeral viewer-session data and not yet an engineering record;
- existing stage sidecar contribution as an Inspect/Technical-details region when it contains truthful stage-owned context that cannot yet be normalized into engineering properties;
- a clear no-selection state.

096 must **not** label UUID/resource metadata as Geometry/Hydraulics/Thermal/Optical/Fouling properties, infer equipment/stream/model identity, invent semantic provenance, or expose fake editable fields. Human-readable engineering Properties arrive through 071b/092/058c.

## 4. Runs containment

`RunsWorkbench.tsx` currently renders projected Inputs/Bindings/Results and each log body inline, including raw `<pre>` content; artifact SHA/source metadata is also inline. These are the concrete expansion/overflow surfaces.

Minimum correction:

- default-bounded technical payload/log containers with internal scroll;
- explicit `View raw` / `Expand` disclosure for complete access;
- expansion remains locally bounded (or uses an existing/simple local dialog/drawer pattern) and must not push Analytics far below the work area;
- run label/status and meaningful projected value/unit information stay primary;
- run id, model-version id, SHA/digest/source identifiers move to Technical details where practical without losing copy/inspection access.

No API or payload projection semantics change.

## 5. Review authority available now

096 may prioritize only fields already supplied by 054 proposal authority: proposal title/summary or proposed content, human-readable scope when present, existing decision state/actions, and evidence already returned by the current proposal contract. A `current → proposed` comparison is shown only when both values already exist authoritatively in the current proposal/stage data. Impact must be omitted unless current authority supplies it; no client inference or generated impact claim is allowed.

Opaque proposal/request/job ids, digests and exact timestamps remain available under Technical details. Accept/Reject authority and stale-action ownership remain unchanged.

## 6. Preserved stale/in-flight behavior

The implementation must preserve all current 091/083 ownership invariants:

- exactly one App-owned Jarvis controller and one interaction dispatch per accepted submit;
- close/reopen does not cancel or redispatch an in-flight submit;
- route/workspace/thread/selection generations continue to reject stale list/detail/preview/submit completions;
- context toggle/refresh remain locked while submitting as currently hardened;
- responsive Jarvis/Properties tab switches do not remount/reset the controller or mutate request identity;
- sidecar Escape returns focus through existing Layout ownership;
- disclosure/tab state performs zero backend/provider/runner/proposal mutation.

Properties must never repaint from stale selection/stage content after current route/selection ownership changes.

## 10. Failure/race handling

- If split sizing cannot be kept usable at compact height, degrade to tabs; do not squeeze two unusable panes.
- If a current stage contribution cannot be mapped truthfully to Properties, keep it under Inspect/Technical details or omit it; never fabricate a semantic label.
- If raw payload expansion would grow the document materially, use a bounded local region/dialog rather than page expansion.
- If presentation changes expose a real 091 stale/redispatch defect, stop and apply only the minimum fix within existing 091 authority, then invalidate all old exact-head evidence.
- If Review lacks current value/impact, omission is correct behavior.

## 11. Rollback
