## 4. Minimum-necessary decision

### Infrastructure

A new narrow protection module and one server-owned encrypted file are necessary. A database table,
credential daemon, cloud vault, OS service, key-management server or general secret catalogue is not.

### Dependency

The implementation must first use Python standard-library `ctypes` for the two DPAPI calls. No new
package is authorized at readiness.

If implementation evidence proves the standard-library path cannot correctly enforce buffer release,
noninteractive current-user scope or test seams, stop and submit a new minimum-necessary decision
before adding a package.

### State store

The encrypted file is not a second canonical engineering-data store. It contains one fixed
server-owned provider secret and is not queryable, extensible by caller input or part of SQLite.

## 5. Frozen implementation decisions

1. Production Windows protection is current-user DPAPI.
2. `CRYPTPROTECT_UI_FORBIDDEN` is required.
3. `CRYPTPROTECT_LOCAL_MACHINE` is forbidden.
4. Unsupported production platforms provide environment-only operation and no weak persistence.
5. The deterministic protector is reachable only by explicit test injection.
6. Canonical location is `<data_root>/secrets/scaleway-api-key.v1.json` through `JarvisPaths`.
7. Persisted data uses the exact inner payload and outer envelope from spec 082.
8. Writes use verified same-directory atomic replacement and preserve the previous credential on
   every handled failure.
9. The runtime-memory dictionary is removed from effective product resolution.
10. Environment value remains strictly authoritative.
11. POST under environment override is conflict and does not mutate persisted state.
12. DELETE removes persisted state but never alters the environment.
13. API responses contain no key-derived preview.
14. Corrupted, unavailable and absent remain distinct.
15. `secrets/` remains excluded from snapshots.
16. Successful restore removes persisted state and requires re-entry unless environment supplies the
    key.
17. No schema migration or frontend file is permitted.

## 7. Test strategy

### Linux CI

Use an explicitly constructed deterministic protector to test:

- envelope and inner-payload contracts;
- restart through a newly constructed store;
- corruption and unsupported-state mapping;
- atomic failure preservation;
- path attacks;
- environment precedence;
- API and event secrecy;
- recovery snapshot exclusion and restore removal;
- provider secret-reference compatibility without provider dispatch.

Product-default Linux persistence must remain unavailable; tests must not enable the fake through an
environment variable or product configuration.

### Windows-specific proof

Add tests or a bounded script that exercise real DPAPI on Windows and prove:

- round trip under the current user;
- fresh-process read under the same account;
- noninteractive operation;
- no `LOCAL_MACHINE` flag;
- safe unavailable outcome when decryption cannot proceed;
- output-buffer release.

Windows-only tests may be skipped on Linux CI but must be executable locally without editing product
code.

### Final operator checkpoint

The Windows P0 runbook remains the sole live-provider checkpoint:

- save real key;
- terminate backend;
- start a new backend process;
- verify `secure_persisted`;
- make one explicitly authorized bounded AI call without re-entry;
- verify safe ledger evidence.

The agent proceeds through implementation, offline tests, CI and review without waiting. It contacts
the maintainer only when the real credential/spend checkpoint is reached or if a security issue is
found.

## 8. Known risks and dispositions

### DPAPI portability

Accepted: persisted credentials are intentionally not portable between arbitrary user/machine
contexts. Backups omit them and restore requires re-entry.

### Same-user malware

Out of scope and stated explicitly. DPAPI at-rest protection does not defend against arbitrary code
already running as the operator.

### Python memory erasure

No secure-erasure claim. Use bounded lifetimes and best-effort buffer cleanup without pretending all
copies can be zeroed.

### Windows path permissions

Restrictive modes are best effort; DPAPI current-user protection is the cryptographic boundary. The
implementation must reject path redirection and irregular files.

### Existing frontend expectations

The endpoints remain stable. `masked_preview` may remain as a nullable compatibility field but cannot
contain secret-derived data. A later Settings slice owns presentation changes.

## 10. Stop conditions during implementation

The implementation must stop rather than expand scope if:

- current-user DPAPI cannot meet the contract without a new dependency;
- a weak fallback is required for Linux product operation;
- snapshots must transport the credential;
- a second provider-execution path is needed;
- frontend code becomes required for persistence;
- a schema migration becomes necessary;
- plaintext or secret-derived data appears outside the protected payload;
- atomic replacement cannot preserve a prior valid credential;
- the final live checkpoint would require bypassing budget, egress or sensitivity controls.
