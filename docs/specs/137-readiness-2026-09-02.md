## Fresh evidence

The accepted 128 AE002 contract requires generic HTTP clients/provider SDK aliases not to bypass architecture enforcement. Fresh inspection of `scripts/check_architecture_enforcement.py` confirms the live scanner only recognizes `httpx`/`requests` request verbs plus provider-import `.complete()` calls. Fresh inspection of `backend/tests/test_architecture_enforcement_gate.py` confirms no deterministic coverage for the additional generic families frozen by spec 137.

This remains a live material correctness gap because first-party code can add direct dispatch through the uncovered families while the AE002 gate remains green.

The pre-readiness full-tree `urlopen` inventory was completed at exact-symbol granularity, not file granularity. The six affected files contain ten current-master symbols:

- `scripts/cheap_review.py::gh_request`
- `scripts/cheap_review.py::call_model`
- `scripts/cheap_review.py::call_model_with_retry`
- `scripts/daily_development_continuation.py::_request`
- `scripts/daily_development_continuation.py::_load_jwks`
- `scripts/daily_development_continuation.py::_post_comment`
- `scripts/verify_merge_authority.py::_request_json`
- `scripts/codex_pr_autopush.py::gh_request`
- `scripts/local_model_structured_output_probe.py::call_ollama_chat`
- `scripts/router_policy_local_responder.py::_stdlib_json_post_client`

The first eight are existing repository-control/review/079/134/022 network tooling. The two remaining symbols are localhost evaluation/control transports, but neither is safe to exact-exempt merely from current caller behavior. `call_ollama_chat(..., url=...)` accepts an arbitrary supplied URL. `_stdlib_json_post_client(endpoint, ...)` is directly importable and currently accepts any endpoint even though its present higher-level caller validates first. The current architecture config accepts only exact `path::symbol` entries, validates target existence, and forbids wildcards. An eleventh newly exposed AE002 exception is not authorized and must stop implementation for re-derivation.

The scanner's import normalizer also has a concrete dotted-import bug relevant to this repair: `import urllib.request` binds the top-level name `urllib`, while the current alias map records that name as the full `urllib.request` module and can duplicate the `.request` component during dotted-call reconstruction. Current-head semantic review found the symmetric regression risk: `provider_import` currently derives its full provider-module knowledge from that same alias map. Replacing the mapping with Python-bound-name semantics without retaining a separate full imported-module inventory would make an unaliased `import app.modules.ai.providers.foo` stop triggering the existing `.complete()` AE002 path. Readiness therefore requires both facts to remain separate and tested.

The socket inventory confirms that connection-only scope is incomplete as a closure claim: both `socket.socket().sendto(payload, destination)` and, where supported, `socket.socket().sendmsg([payload], [], flags, destination)` can transmit externally without `connect` or `create_connection`. `sendto` and destination-bearing `sendmsg` are frozen into the required detector and fixture matrix.

Current-head review also proves destination escape at both proposed localhost retained owners. Standard `urllib.request` follows HTTP redirects by default, so a request whose initial URL passed loopback validation can receive a 3xx with an external `Location` and issue a second request outside loopback while the actual network call sits inside an exact AE002 exception. Initial-URL validation alone therefore does not make either exact exception truthful. Readiness requires deterministic redirect rejection at both retained localhost urllib transport boundaries, or equivalently fail-closed per-hop loopback validation. The minimum authorized design is redirect rejection; no generic network-policy or DNS/rebinding framework is needed.

A redirect-safe urllib implementation commonly uses a custom opener/redirect handler and dispatches through `OpenerDirector.open` instead of convenience `urlopen`. Replacing a detected `urlopen` with an unrecognized opener `.open` would itself create a new AE002 bypass. Readiness therefore freezes concrete `urllib.request` opener dispatch (`build_opener(...)` / same-file bound opener `.open`) into the scanner and hostile fixture surface, while keeping the two retained localhost functions as the same exact exceptions.

## Frozen design

- Extend the existing AST classifier; do not create another network-policy implementation.
- Correct import alias normalization so unaliased dotted imports follow Python's bound-name behavior and aliased/from-import forms still resolve to their full target.
- Preserve full imported-module targets separately from bound-name aliases so the existing provider-import `.complete()` detector remains effective for unaliased dotted provider imports.
- Add a small deterministic same-file constructor/binding map only where needed to recognize `urllib.request` openers, `urllib3.PoolManager`, `socket.socket`, `aiohttp.ClientSession`, and `http.client.HTTPConnection` / `HTTPSConnection` instance calls.
- Match only concrete frozen network methods/types, not generic `.open`, `.request` or `.connect` method names.
- Cover `urllib.request.urlopen` plus concrete opener `.open`, `urllib3` request dispatch, `socket.create_connection` plus socket-instance connect/connect_ex/sendto and destination-bearing sendmsg, aiohttp session request verbs, `websockets.connect`, and http.client connection request/connect.
- Preserve current accepted-owner behavior and exact-exception semantics.
- Before excepting `scripts/local_model_structured_output_probe.py::call_ollama_chat`, parse its supplied URL locally and fail closed unless the host is literal `localhost` or a standard-library-classified loopback IP; reject malformed/missing hosts, user-info ambiguity, and non-loopback hosts before request construction/dispatch. No DNS/network lookup is part of validation.
- Before excepting `scripts/router_policy_local_responder.py::_stdlib_json_post_client`, make that function itself invoke the already-existing `_validate_endpoint(endpoint)` before request construction/dispatch. This intentionally repeats the current higher-level validation at the exact-exempted transport security boundary; it does not introduce a second endpoint policy.
- Before excepting either localhost urllib transport, ensure HTTP redirects are not automatically followed. A 3xx returned from the validated loopback endpoint must terminate as a typed/local transport failure before a second request can be emitted. An equivalently fail-closed per-hop loopback check is acceptable only if it is smaller and deterministically testable; do not build a generic redirect-policy service.
- Preserve `router_policy_local_responder.py`'s current `_validate_endpoint` contract exactly: `http`, localhost host, `/api/generate`, no credentials/query/fragment. 137 moves that same check to the transport boundary as defense in depth; it does not change allowed endpoints.
- If redirect rejection uses a custom urllib opener, its `.open` call remains detectable by AE002 outside accepted/exact-exempted owners; do not solve one bypass by introducing another scanner blind spot.
- The ten inventoried existing symbols may be exact exceptions only subject to the two localhost destination guards above; no additional exception is implicitly authorized.
- Dynamic/interprocedural dispatch not resolved by this bounded static pattern set remains residual risk rather than justification for a taint framework.
