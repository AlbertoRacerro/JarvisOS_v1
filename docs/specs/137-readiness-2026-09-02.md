The scanner's import normalizer also has a concrete dotted-import bug relevant to this repair: `import urllib.request` binds the top-level name `urllib`, while the current alias map records that name as the full `urllib.request` module and can duplicate the `.request` component during dotted-call reconstruction. The implementation must correct that Python binding semantic while preserving aliased imports.

The socket inventory confirms that connection-only scope is incomplete as a closure claim: both `socket.socket().sendto(payload, destination)` and, where supported, `socket.socket().sendmsg([payload], [], flags, destination)` can transmit externally without `connect` or `create_connection`. `sendto` and destination-bearing `sendmsg` are frozen into the required detector and fixture matrix.

## Frozen design

- Extend the existing AST classifier; do not create another network-policy implementation.
- Correct import alias normalization so unaliased dotted imports follow Python's bound-name behavior and aliased/from-import forms still resolve to their full target.
- Add a small deterministic same-file constructor-binding map only where needed to recognize `urllib3.PoolManager`, `socket.socket`, `aiohttp.ClientSession`, and `http.client.HTTPConnection` / `HTTPSConnection` instance calls.
- Match only concrete frozen network methods/types, not generic `.request` or `.connect` method names.
- Cover `urllib.request.urlopen`, `urllib3` request dispatch, `socket.create_connection` plus socket-instance connect/connect_ex/sendto and destination-bearing sendmsg, aiohttp session request verbs, `websockets.connect`, and http.client connection request/connect.
- Preserve current accepted-owner behavior and exact-exception semantics.
- The ten inventoried existing symbols may be exact exceptions; no additional exception is implicitly authorized.
- Dynamic/interprocedural dispatch not resolved by this bounded static pattern set remains residual risk rather than justification for a taint framework.
