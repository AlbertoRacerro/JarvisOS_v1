The relevant authority is already explicit:

## Exact trustworthy observation contract

An observation is eligible only when all of the following hold:

1. the run belongs to the current App-owned workspace;
2. run `status === "succeeded"`;
3. `model_version_id` is non-null and non-empty;
4. `output_payload` is non-null and at most `1_048_576` UTF-8 bytes, matching the runner output ceiling;
5. payload parses as a non-array object;
6. `schema_version === 1`;
7. payload `status === "succeeded"`;
8. `outputs` is a non-array object;
9. output key is a non-empty bounded string;
10. the output value is a non-array object containing exactly the required comparison fields `value` and `unit` plus any ignored producer fields;
11. `value` is a finite JSON number and not a boolean;
12. `unit` is a non-empty bounded string and is used exactly as persisted.

The first implementation does not coerce numeric strings, nulls, booleans, arrays, objects, NaN-like text, infinity-like text or malformed JSON into values.

The analytics parser works from `output_payload` itself. It must not scrape 088 rendered `<pre>` content and must not use 088 presentation truncation as engineering input.

## Metric identity

The trustworthy first-slice metric identity is exactly:

```text
(model_version_id, output_key)
```

This is intentionally stricter than grouping by output key alone. A model version is the reviewed immutable implementation identity; two different versions may reuse a key while changing semantics, correlation, validity domain or definition.

Therefore selected runs with different `model_version_id` values are not merged into one numeric comparison in 089. The UI visibly reports that one model version is required for a direct comparison.

No metric identity may be derived from:

- unit alone;
- display labels;
- JSON traversal position;
- run label;
- model name guessed from notes;
- diagnostics prose;
- neighboring fields;
- magnitude.

## Unit compatibility

The first implementation uses **exact unit-string equality only**.

This follows existing model/run authority: reviewed bundled models emit canonical units and 071 explicitly performs no conversion. There is no need to create another unit authority in 089.

Examples:

- `Pa` with `Pa`: comparable when metric identity also matches;
- `Pa` with `kPa`: rejected visibly, even though physically convertible;
- `m` with `m`: not comparable when output keys differ;
- missing/blank unit: observation rejected.

089 performs no alias normalization, case folding, dimensional inference or conversion table. A future quantity/unit authority may broaden this only through a later explicit specification.

## Selected-run and payload bounds

Freeze the first implementation at:

- maximum selected runs: **6**;
- maximum output keys inspected per run: **128**;
- maximum output key length: **160** Unicode code points;
- maximum unit length: **64** Unicode code points;
- maximum displayed run label: **160** Unicode code points, with canonical run id retained in bounded technical text;
- raw `output_payload` ceiling: **1 MiB UTF-8**, matching backend runner authority.

If a selected run exceeds an extraction bound, the run is marked unsupported for analytics and the affected comparison is rejected/incomplete. Do not silently truncate a metric set and present the remainder as a complete comparison.

Six runs are sufficient to compare a small engineering alternative set while keeping the dock legible and preventing a general dashboard/BI surface.

## Comparison algorithm

For the explicitly selected run set:

1. zero selected runs: instructional empty state;
2. one selected run: explain that at least two runs are required;
3. if selected runs do not share one exact `model_version_id`: reject the direct comparison visibly;
4. parse each selected run independently under the observation contract;
5. compute the sorted union of allowed output keys;
6. for each key, require one valid observation from every selected run;
7. require exact unit equality across all observations for the key;
8. otherwise emit a bounded rejected group with the run(s), persisted units where available and reason;
9. for a valid group, display each exact persisted value and unit plus only deterministic direct summaries:
   - minimum;
   - maximum;
   - absolute range `max - min`.

No mean, median, standard deviation, percentile, percentage change, confidence interval, regression, trend, score or ranking is authorized.

Missing, malformed or incompatible observations are not replaced with zero, `—` inside the numeric set, or silently dropped.

## Data acquisition and async ownership

Use existing `listRuns(workspaceId)` from 088. It already returns `model_version_id`, `status` and `output_payload`; a second N-run detail fetch is unnecessary.

The analytics component owns one workspace-scoped list request with:

- monotonic request generation;
- captured workspace identity;
- synchronous clearing of prior runs, selection, parse results, errors and comparison groups before a new workspace read;
- acceptance only when generation and workspace identity still match.

Required stale case:

```text
workspace A request 1
→ workspace B request
→ workspace A request 2
→ late completion of A request 1
```

The late first-A response is rejected by generation even though workspace identity has returned to A.

Run selection and comparison recomputation are local over the accepted run list, so no X→Y network detail race exists in the minimum implementation. Selection changes must still synchronously replace derived analytics; stale derived groups cannot remain visible under a new selected set.

On refresh, retain only selected run IDs still present in the newly accepted list. A disappeared run is visibly removed from the selection and the comparison recomputed; it cannot survive as stale evidence.
