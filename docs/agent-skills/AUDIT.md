## Desk comparison on one representative Studio task

Task: add a view that loads a Studio model, library and runtime status, then lets an operator edit annotations while a prior request is pending.

| Baseline without skill | With the selected React skill | What the comparison actually establishes |
| --- | --- | --- |
| A normal code review may notice independent fetches and stale closure risks, but has no explicit reminder for either. | The two pinned rules prompt `Promise.all` for independent reads and a functional setter when edits depend on prior state. The instruction also warns that revision-sensitive writes must remain ordered. | A desk review of likely decision paths, **not** a timed benchmark or executed A/B test. Performance and correctness gains require a concrete UI change and browser proof. |

For the same task, the browser skill turns “it looks right” into a reproducible local route, visible snapshots, a real interaction, screenshot, backend record, and exact HEAD. No browser run was performed for this audit because no product UI changed here. Neither skill claims scientific validation.
